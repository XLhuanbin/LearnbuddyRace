## 一、目标匹配与执行可行性已拆开

### 1.1 拆成了什么

| 表达 | 回答的问题 | 是否受硬件影响 |
| --- | --- | --- |
| **目标匹配** `goalMatch` | 为什么值得研究（适合阅读 / 方法借鉴 / 进一步调查 / 背景 / 关系不大） | **不受**（阅读推荐不会被预训练硬件门槛阻断） |
| **执行可行性** `execution[]` | 在我的条件下能做哪一步 | 按操作分别判断 |

执行可行性按**四种用户操作**分别给出，每种一个状态：

| 状态 | 含义 |
| --- | --- |
| `evidence_supported` | 论文给出了与该操作阶段相符、规模可比的算力证据 |
| `insufficient_evidence` | 论文没有报告该阶段的算力 |
| `known_gap` | 已知用户资源低于论文报告值 |
| `unverified` | 缺少必要条件，尚未验证 |

判定规则（**复用既有数据与判断，没有新增一套系统**）：

- 阅读阶段：只看论文文本是否可用 → 永不因算力判为差距；
- 微调阶段：**只看微调阶段的算力条目**；论文没报告时明确写「不能用预训练成本代替微调成本」；
- 预训练阶段：只看预训练阶段算力，并复用原有的规模对照与「显存/并行/配置证据」判定。

界面同时写明边界：**这些是「基于论文证据的判断」，系统不会实际运行训练或推理，也没有读取你的机器信息；
「论文证据支持该阶段」不等于「已经验证能在你的设备上跑通」**。

### 1.2 一个具体例子（预置用户：只有笔记本，无 GPU 集群；两周，每天约 2 小时）

论文：RoBERTa（`arXiv:1907.11692`）

| 维度 | 结果 |
| --- | --- |
| **目标匹配** | **值得进一步调查**。理由：核心思路是系统研究预训练关键设计选择（动态掩码、NSP、输入格式、批大小、数据规模与训练步数），与「想了解预训练语言模型训练思路」的兴趣相关；同时给出边界——论文把架构改动留作未来工作，研究范围集中在预训练设计选择 |
| 阅读与理解方法 | **论文证据支持**（只依赖论文文本，不受算力限制） |
| 使用现有权重推理 | **尚未验证**（本次抽取不含「可直接使用的权重 / 推理成本」条目） |
| 在自有数据上微调 | **论文未报告该阶段算力**——并明确说明不能用预训练成本代替 |
| 从头预训练 | **已知存在资源差距**（论文报告 1024×V100 约一天 / DGX-1 8×32GB V100；用户仅笔记本） |

这正是本轮要的效果：**同一篇论文既能有吸引人的阅读价值，又能如实说出「哪一步我做不了」**，两者不再互相抵消。

### 1.3 预置推荐是否回答了那两个问题

走查确认（`npm run e2e` E13）：决策页每个候选都同时展示「为什么值得研究」与「在你的条件下能做哪一步」，
四条操作分行显示，并带有「不等于已经验证能在你的设备上跑通」的边界说明。

## 二、恢复了安全的「重新分析」入口

| 要求 | 实现 |
| --- | --- |
| 不再要求先移除论文再导入 | 已分析论文直接提供「**重新分析**」按钮（缓存结果按钮文案为「重新用模型分析」） |
| 说明会消耗模型额度 | 采用**两步确认**：点击后先显示「会消耗模型额度；分析期间保留原结果，人工修正不会被覆盖」→ 需再点「确认重新分析」；可随时「取消」 |
| 分析期间保留原结果 | 新结果只在**成功后**写入存储；运行中原结果不变 |
| 失败/取消不丢失原结果 | 失败与取消都只更新任务状态，不触碰已保存结果 |
| 成功后更新结果并处理下游 | 更新该论文结果，并显示「下游待更新」横幅：**方法关系**与**方法决策**需重新生成；**跨论文比较 / 分歧**由程序按当前数据实时重算（横幅明确写出，要求人工复核受影响论文对） |
| 人工修正不被静默覆盖 | 重新分析时把旧结果的 `overrides` 合并进新结果，并在日志写出「已保留 N 条人工修正」 |

### 测试

- `mergeReanalysisResult`：人工修正保留、模型输出被替换、`cached` 清除、首次分析也能合并（4 项）；
- 文案边界：取消说明「未完成」且**不夸大**成「已终止服务端计算或计费」；失败说明「原结果保持不变」（2 项）；
- 下游提示：关系/决策需重新生成、比较为实时重算、人工修正已保留（3 项）；
- 真实浏览器（线上）：入口存在 → 点击出现额度提示 → 取消后**没有发起调用**且原结果仍在（5 项，本轮流程验证 35/35 通过）。

## 三、超时与取消机制

### 3.1 实际行为（客户端已具备）

| 行为 | 实现 | 是否夸大 |
| --- | --- | --- |
| 明确的超时 | 每次调用独立超时（默认 120s，抽取场景 180s），超时即中断等待并抛错 | 否 |
| 超时后的状态 | 归类为「失败（未完成）」，界面**不会一直显示运行中**，也不会把未完成调用算作成功 | 否 |
| 停止等待（取消） | 用户点击「停止等待」→ 中止本地等待；取消**不再重试** | 界面文案明确：**「不代表服务端已停止计算或不再计费」** |
| 重试 | 仅网络/超时/服务端错误重试，最多 3 次、退避 1.2s/2.4s；鉴权与配置错误**立即失败不重试** | 每次尝试都写 trace |

### 3.2 验证方式（mock 与真实接口**分开记录**）

用本地 mock 服务做确定性验证（`npm test` 第 18 节，9 项全通过）：

| 用例 | 结果 |
| --- | --- |
| 超时中断等待并抛错 | 通过（实测 410ms 结束） |
| 超时错误说明「未完成」、不被当成成功 | 通过 |
| 外部取消能中断等待 | 通过 |
| 取消不重试（只请求 1 次） | 通过 |
| 鉴权错误立即失败不重试 | 通过（kind=auth，请求次数 1） |
| 服务端错误退避重试后成功 | 通过（3 次尝试，trace 完整） |
| 超时归类为「失败（未完成）」而非运行中/成功 | 通过 |
| 取消归类为「已停止等待」 | 通过 |
| 未知错误归类为失败（不静默） | 通过 |

## 七、本轮补充（同日续做，收掉两处可行动缺项）

### 7.1 推理行不再一律「未验证」：补上「权重能不能拿到」的原文证据

**先查了什么**：扫描 5 篇预置论文全文，「released / publicly available / GitHub / HuggingFace」这类表述
BERT 命中 8 处、RoBERTa 12 处、DistilBERT 16 处、Transformer 4 处、GPT-3 12 处 —— **但抽取维度里没有这一项**，
所以「使用现有权重推理」一直是「尚未验证」。这是**我们缺维度**，不是论文没写。

**做法（不新增模型调用、不新增维度、不影响可比性维度）**：新增确定性全文检索
`src/core/inferenceReadiness.ts`，判定一句话是否在说「**本论文提供了**模型/权重/代码」，要求落在三种句式之一：
自称提供（we/our + released/open-sourced + 产物作宾语）、产物 + 系动词 available、可用措辞 + 仓库链接；
并排除「released pretrained language models」（说的是别人的模型）、「published models」（比较）、
「test set when publicly available」（测试集）、「release the synthetic datasets」（数据集）以及否定表述。

**结果**（重跑一次示例决策）：

| 论文 | 推理行状态 | 原文依据 |
| --- | --- | --- |
| BERT | 论文未报告该阶段算力（有依据） | 「The code and pre-trained models are available at https://github…」(p.2) |
| DistilBERT | 同上 | 「We have made the trained weights available along with the training code…」(p.2) |
| RoBERTa | 同上 | 「Our models and code are available at: https://github…」(p.1) |
| Transformer | 同上 | 「The code we used to train and evaluate our models is available at https://github…」(p.10) |
| GPT-3 | **尚未验证**（如实） | 全文未声明发布权重（该模型确实只通过 API 提供） |

文案同时写明边界：**「可获取 ≠ 可运行」**——论文没有报告推理阶段的算力与资源需求，
能不能在用户设备上跑通仍未验证。界面展示引文与页码，并可点开完整上下文。

### 7.2 真实浏览器验证「重新分析成功」路径（此前只验证了失败/取消）

此前验过失败与取消；本轮在**线上站点用真实模型**跑通成功路径：

1. 先对某字段做一次**人工修正**（保存后出现「已人工修正」）；
2. 点「重新分析」→「确认重新分析」（消耗一次模型额度）；
3. 成功完成后核对：**人工修正仍然存在**、仍能看到「AI 原值 → 修正值」的修正记录、
   顶部出现「有论文的结果已更新」横幅（列出方法关系/方法决策需重新生成、跨论文比较为实时重算、**人工修正已保留**）、
   且界面与日志都没有出现密钥明文。

### 7.3 顺带修掉的一处不一致

资源类理由若引用的是 `datasets` 这类**非算力条件**，此前会把该引文挂上去并标为「不匹配」；
按「不能因字段有值就算通过」的要求，现在**不挂载该证据**（只记录定位结果与原因说明），
界面显示为「该理由没有可核验的证据支持」。
