## 1. 实际确认存在的问题（先复现、后修改）

复现脚本 `.build/repro-probe-status.mjs`（不提交），走真实 `extractMethod` + 本地 mock 模型服务。

**词表错位**：`prompts.ts` 的字段 schema 写的是 `"status": "ok|missing"`，而同一文件的 `STATUS_RULES` 定义的是
`reported / not_reported / not_extracted / unclear`；解析器此前**只认 `'missing'`**。内部 `FieldStatus` 只有
`verified / unverified / no_evidence / missing` 四个槽。

| 输入 | 修复前结果 | 问题 |
| --- | --- | --- |
| `status:'unclear'` + **可定位**引文 | `status='verified'` | **最严重**：模型自己说「找到了内容但无法确认」，系统却标成「可核验」，还会被 `Library.verifiedOf()` 计入「已核验字段数」。这正是「定位到了文字」与「这段文字足以支撑结论」必须分开的情形。 |
| `status:'not_extracted'`（片段里没有） | `status='missing'`, note=`论文未报告` | 把「本次片段中没有」讲成「论文没写」——项目反复强调不能混的两种情况被混了，校验说明也跟着说错。 |
| `status:'not_reported'`（论文明确没有） | 靠模型顺带给的 note 侥幸对 | 没给 note 时无法与 `missing` 区分，语义不稳定。 |
| `status:'not_extracted'` 但**同时给了** value+引文 | `status='verified'` | 模型自相矛盾时，静默采信了内容。 |

**同类空值 / 类型风险（`item?.note?.trim()` 这一类）**，修复前实测：

| 输入 | 修复前 |
| --- | --- |
| `note: 123` | `TypeError: item?.note?.trim is not a function` —— **整次分析崩掉** |
| `status: 5` | `TypeError: (… || '').toLowerCase is not a function` |
| `fieldStatus: ['missing']` | `TypeError: (… || '').toLowerCase is not a function` |
| `value: {name:'FooNet'}` | `value='[object Object]'` 且 `status='verified'` —— **等于编造字段值** |
| `quote: 42` | 按「有引文但定位失败」处理，会把错误解释成「模型可能改写了原文」 |

## 3. 归一规则（把 5 个外部状态映射进 4 个内部槽）

| 外部 status | 内部 status | value | evidence | note |
| --- | --- | --- | --- | --- |
| `reported` / `ok` / 未给 | 走原有证据路径（引文定位成功才 `verified`，否则 `unverified`） | 保留 | 挂载 | 模型 note |
| `missing` | `missing` | 丢弃 | — | `论文未报告` |
| `not_reported` | `missing` | 丢弃 | — | `论文明确表示不适用或没有使用（论文未报告）`；模型自带 note 时若不含「未报告」则补上该判据 |
| `not_extracted` | `missing` | 丢弃 | — | `本次片段中未提取到`（下游 validate 据此说「本次片段中未提取到」） |
| `unclear` | **`no_evidence`** | 保留 | **不挂载**（见下） | 模型 note 优先，否则说明「标注为无法确认，需人工回到原文核对」 |

两个关键取舍，都写进了代码注释，供评审推翻：

1. **`unclear` 不挂载已定位的引文**。内部约定「引文已验证 ⇔ 字段状态可核验」，而 `Library.verifiedOf()`、
   `UploadFlowView` 的进度、`UploadFlowView.tsx:600` 的样式都按 `evidence.verified` 统计 —— 挂上就已自相矛盾
   （状态说「未找到证据」、统计却算作「已核验」）。代价是不再展示那半句引文，收益是不会把「模型自认无法确认」的东西算成可核验。
   > 若团队更想保留引文，需要同时改 UI 的统计口径（属产品方向），不在本轮范围。
2. **标签优先，但必须留下说明**。模型一边说 `not_extracted` 一边给出 value+引文时，按缺失处理，
   并在 note 里写明「模型把该条目标为 not_extracted（自认该项不可用），但同时又给出了内容…已按缺失处理」——
   不静默丢弃，也不把它当成已确认的结论。
3. 条件侧（`conditions`）套用同一套规则：`not_reported` / `unclear` 保持原有语义不变，
   补上 `missing` 与 `not_extracted` 的「标签优先」处理，并把 `status` / `quote` / `note` / `scope` / `stage` / `scopeDetail`
   的读取全部换成安全版本（这些位置此前遇到数字同样会抛 `TypeError`）。

## 4. 新增测试（`tests/core.test.ts` 第 30 节，23 项）

- **正向**：`reported`、`ok`、未给状态三种写法 + 可定位引文 → 均可核验；`missing` / `not_reported` / `not_extracted` →
  缺失且 note 分别带对判据（`论文未报告` / 含「未报告」 / 含「片段」）；`fieldStatus` 别名生效。
- **核心**：`unclear` + 可定位引文 → **不是 `verified`**、是 `no_evidence`、且 `evidence === undefined`；`unclear` + 引文无法定位 → 同样不是可核验。
- **自相矛盾输入**：`not_extracted` 又给内容 → 按缺失处理且 note 写明原因。
- **异常输入**：`note` 是数字、`status` 是数字、`fieldStatus` 是数组、`value` 是对象、`quote` 是数字 —— 全部**不再抛 `TypeError`**，
  且 `value` 是对象时**不得**变成 `"[object Object]"`。
- **条件侧**：`missing`（即使给了 values/quote）→ 不当作已确认且有冲突说明；`not_reported` → 明确「论文没有」；
  `unclear` → 保留「无法确认」不升级；`reported` + 可定位引文 → 仍为已验证（正向路径未被影响）。

## 6. 是否改变公共类型、缓存结构或版本号

- **公共类型：未变**（`types.ts` 未动，`FieldStatus` 仍是原来 4 个槽 —— 这正是必须做「映射」而不是「加状态」的原因）。
- **缓存结构 / 预置缓存：未变**（一行未动，本轮未运行 `revalidate.mjs`）。
- **版本号：全部未变** —— `PROMPT_VERSION` 仍为 `v3.0.0`（提示词文本一字未改，按指令不升）；
  `RULES_VERSION` 保持 `r3.1.0`；`CACHE_VERSION` 仍为 `3`。

  **为什么 `RULES_VERSION` 也不需要升**（说明这个判断，供团队复核）：`RULES_VERSION` 管的是
  「缓存里的判定类结论在当前规则下是否仍然有效」，而本次改的是**抽取期**如何解释模型自报的状态标签 ——
  缓存里的字段早已是归一后的状态，`revalidate` 对它们重跑的是 `validate.ts`（未改动），因此缓存结论仍然有效。
  规则语义档那次是真的改了判定规则（可比性/是否采信模型自报），所以升了版本。若团队认为这属于「影响结论的改动」，
  升一行 + 重算一次即可，代价是必须重跑两个语料的 `revalidate`（本轮按指令不做）。

## 7. 是否需要核心 B / 产品方向接入

- **核心 B：不需要**。
- **产品方向：不需要改代码**，但有一处**已知的文案不精确**，建议排期时顺手修（属 `validate.ts`，不在本轮「只改解析器」的范围）：
  当字段因 `unclear` 被处理成 `no_evidence` 时，`validateMethod` 仍会输出「模型给出了内容但没有提供任何原文引文」——
  实际是模型**给了**引文但我们因「无法确认」不挂载。字段自身的 note 已写清真实原因（且会被渲染），
  所以误导有限。修法：在 `validate.ts` 里按 note 是否含「无法确认」走另一句文案（约 2 行）。
- **演示前无需特别准备**：预置样例的数据与本轮改动无关（改的是**新抽取**时的解析口径）。
