## 二、可操作的演示流程

1. 打开线上链接 → 左侧导航进入 **「实验比较」**（默认语料集已是「正式案例：图像分类」，5 篇）。
2. 页面顶部是本次要回答的问题：*这些方法都报告 ImageNet 分类表现，我能直接按准确率选最好的吗？*
   下方「值得先看的比较」由程序按条件差异自动挑出（**不是排名**），点一下即可载入对照。
3. 在实验列表里点两条记录（也可自己挑）→ 出现对照面板：
   - **结论**：已知条件下可直接比较 / 只能结合条件讨论 / 信息不足 / 不能直接比较；
   - **条件差异表**：预训练数据、训练数据、评估集与划分、分辨率、额外数据、蒸馏、测试时增强、单模型/集成；
   - **信息不足项**：哪一方未知，导致不能直接判断；
   - **吞吐量提示**：测量硬件/批量不同时明确写「不能直接比较快慢」。
4. 点任一条的 **「查看原文」** → 证据弹层：页码、原文上下文高亮、是否通过全文定位校验。
5. 切到 **「方法关系图」** 看方法间关系（原文明示 / 系统推断 / 待核查三档，虚线/点线区分）。
6. 切到 **「方法决策」** 看「为什么值得研究」（目标匹配）与「在你的条件下能做哪一步」
   （阅读 / 推理 / 微调 / 从头预训练分别判定）。
7. 切到 **「分歧与待调查问题」** 看条件性分歧与「各自局限」。
8. 在「论文库」顶部可**切换语料集**：正式案例 ↔ 开发回归样例（NLP），两者结果各自独立、不混合生成关系与推荐。

## 三、最值得向评委展示的发现（每条都有原文依据）

### 发现 1：同一张 ImageNet-1K 榜单里，预训练数据不同 → 不能当架构证据

| 记录 | 数值 | 预训练数据 | 分辨率 | 行列核查 |
| --- | --- | --- | --- | --- |
| ViT-H/14 | ImageNet 88.55 ± 0.04 | **JFT-300M** | 518 | ⚠️ 待核查（数值原样保留） |
| Swin-L | ImageNet top-1 87.3 | **ImageNet-22K → 1K 微调** | 384 | ⚠️ 待核查 |
| ConvNeXt-XL | top-1 87.8 | **ImageNet-22K → 1K 微调** | 384² | ⚠️ 待核查 |
| DeiT-B | top-1 81.8 | **none（无额外数据）** | 224 | ✅ 数据核对通过 |

**原文依据**：每条记录都带原文引文与页码，例如 DeiT 的版面带为
`DeiT-B 86M 224 2 292.3 81.8 86.7 71.5`（p.12）；Swin-L 的预训练数据来自论文对其「22K 预训练」的说明。
**为什么重要**：87.8 与 81.8 相差 6 个点，但一个是 22K 预训练 + 384²，一个是只有 1K + 224²。
把这两个数字并列成「ConvNeXt 比 DeiT 强」是把**数据与分辨率**的功劳算到了架构上。
系统在对照面板里把这条判为「只能结合条件讨论」，并逐项列出差异。

### 发现 2：DeiT-B⚗ 的增益里含一个 CNN 教师

- 系统记录：`DeiT-B⚗ = top-1 accuracy 83.4`，条件为「**使用硬蒸馏，教师为 RegNetY-16GF**」（p.12）。
- 对照场景：若把它与 `Swin-B = 83.5` 并列成「Transformer 之间的比较」，其中一侧实际上**引入了 CNN 教师**，
  这不再是「纯架构」对照。
- **为什么重要**：这正是用户问题的答案——「差别在哪里」。系统把蒸馏与教师来源单列为一个条件字段，
  只要两边不一致就会出现在差异表里；缺失时保持「未知」而不是默认「无」。

### 发现 3：指标口径不同——ResNet 报的是 error，不是 accuracy

- 系统记录：`ResNet-152 = top-5 err. 4.49`、`ResNet-50 = top-1 err. 22.85`（p.6），
  而 DeiT/Swin/ConvNeXt 报的是 `top-1 accuracy 81.8 / 81.3 / 82.1`。
- 程序判定：**不能直接比较**，并说明「一个是错误率、一个是准确率，可以互换（100 − err）但方向相反，
  直接并列会得出相反结论，需要先换算并注明口径」。
- **为什么重要**：22.85 与 81.8 放在一起看，会得出「ResNet 差得多」的错误印象，而 100−22.85 = 77.15 才是可比的量。
  这条差异是**本轮人工核查时发现的真实缺陷**（修复过程见 §4 第 2 条）。

### 发现 4：检测结果不混入分类比较

- `Swin-L (HTC++)* = 58.7 box AP @COCO`、`ConvNeXt-T = 50.4 AP_box @COCO` 被标为 `detection`，
  系统在比较时直接判「不能直接比较」（任务不同）。
- 列表默认只显示分类实验，勾选「一并显示非分类结果」才会出现，且带任务标签。

## 四、人工核查中发现的错误与修复

完整清单见 [`VISION-REVIEW-CHECKLIST.md`](VISION-REVIEW-CHECKLIST.md)（含逐条「系统输出 / 原文版面带 / 判断」），
**数据核对与模型核对分开记录，未静默修正任何数值**。

| # | 问题 | 类型 | 处理 |
| --- | --- | --- | --- |
| 1 | DeiT、Swin 的启发式标题抓到摘要句 | 解析 | **已修复**：模型给出的标题经原文验证后校正；保留 `titleFrom` 标记 |
| 2 | ResNet 用 top-1 **error**、其余用 top-1 **accuracy**，程序原先把两者当成同一指标 | 规则 | **已修复**：区分 error/accuracy，比较时给出换算说明并判「不能直接比较」 |
| 3 | 表格行标签核查用「逐字包含」，导致 `Swin-T` 这类短标签一律失败 | 规则 | **已修复**：改为归一化定位 + 要求出现在引文附近（±1500 字符） |
| 4 | 列头搜索范围过小（220pt），真实列头在数值上方约 268pt | 规则 | **已修复**：扩大到 900pt 并过滤句子型候选 |
| 5 | 标题校正后没有重算字段校验，出现「标题未确认」与「已模型校正」并存 | 流程 | **已修复**：校正后重算校验（校验问题 12 → 10，`title_unverified` 归零） |
| 6 | ViT 的一条记录把数据集名当成指标名（`ImageNet=88.55`）、另一条只写 `accuracy` | **模型抽取错误** | **未修复**：按原样展示并在清单里标出；修正需要重跑该篇或人工修正，本轮不静默改数 |
| 7 | Swin 仅用 1K 训练的三条记录，预训练数据为「未知」 | 模型抽取不完整 | **未修复**：标为未知而不是猜（Swin-L 的 22K 预训练已正确抽出） |

## 八、本轮成功标准自评

用户能否通过一个真实案例理解「为什么某些分类结果不能直接比较」，并获得有依据的方法理解与阅读建议：

- **能**：从「实验比较」页选两条记录即可看到条件差异与结论档位，且每个数值都能点开原文依据；
- 三个最有说服力的点分别是：预训练数据不同（JFT-300M vs 22K vs 无）、蒸馏含 CNN 教师、error/accuracy 口径不同；
- 阅读建议侧：决策页的「目标匹配」给出为什么值得研究（不因算力门槛阻断），
  「执行可行性」按阅读/推理/微调/预训练分别说明（例如从头预训练对普通实验室是「已知资源差距」）。
