## 一、审查：当前最影响使用的问题（按影响排序）

审查方式：对每个页面在 1440×900 与 390×844 下逐屏截图，并统计每页文本量与主区按钮
（原始截图与统计见 `docs/ui-audit/`、`docs/ui-audit-loaded/`）。用真实截图定位到的问题：

| # | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| P1 | **首屏没有产品说明，也不回答「从哪开始」** | 首屏第一行是「论文库」，其后 4 个文本块才出现按钮；空状态文案是规格说明（「导入带文本层的 PDF，系统在本地解析…」） | 评委打开后不知道这是什么、该点哪里 |
| P2 | **主入口不突出、名称含糊** | 主按钮叫「加载预置样例语料」，看不出是正式视觉案例还是旧 NLP 样例；语料集切换是卡片里的一行小字 | 评委可能以为系统主案例仍是 BERT/GPT-3 |
| P3 | **导航只有编号 + 短名，没有步骤含义与状态** | 侧栏为「01…09」，没有「已完成/待处理/警告」 | 不知道顺序、不知道下一步 |
| P4 | **实验比较页信息过载、没有操作起点** | 5389 字符 / 184 行；20 条记录全部展开成卡片；只有「查看原文」一个动作；无筛选；「值得先看的比较」为空时不给任何起点 | 这一步是本产品的核心，却最难上手 |
| P5 | **状态表达混乱**：正面的核查说明（「表题已在引文附近定位」）被当成警告色显示 | 行内警告色文字实为已通过项 | 用户误以为到处是问题 |
| P6 | **模型未配置的警告占据首屏**，且没说「不配置也能完整演示」 | 黄色 Banner 三行技术文案 | 评委被引导去做配置而不是看演示 |
| P7 | **选择后的结论在长表格最下方** | 选中两条记录后需滚动 20 行才看到对照卡片 | 演示时看不到结论 |
| P8 | 页面之间没有「下一步」提示 | 各页独立，靠用户自己猜 | 完整演示走不通 |
| P9 | 关键操作依赖位置记忆；焦点不可见（无 `:focus-visible`） | 键盘 Tab 无任何提示 | 可访问性不足 |
| P10 | 长标题/长引文/长条件挤在行内 | 论文标题与证据片段撑满一行 | 按钮被推挤、难以扫描 |

## 三、新用户实际走一遍的步骤（脚本逐项验证）

| 步骤 | 操作 | 结果 |
| --- | --- | --- |
| 1 | 打开页面 | 首屏可见产品说明、三个问题、演示路径、主按钮（不滚动即可看到） |
| 2 | 点「加载正式视觉案例（5 篇，含预置分析结果）」 | 一次性就绪：5 篇论文 + 分析结果，无需配置模型 |
| 3 | 进「论文库」 | 看到语料集名称、正式/回归标记、5 篇论文、每篇的字段状态；底部有「下一步」 |
| 4 | 进「实验比较」 | 顶部即问题句；点推荐对照（或自己点两行） | 
| 5 | 看对照结论 | 结论档位（可直接比较 / 只能结合条件讨论 / 信息不足 / 不能直接比较）+ 条件差异表 + 信息不足项，**无需滚动** |
| 6 | 点「查看原文」 | 证据弹层：页码 + 上下文高亮 + 定位校验标记 + 关闭按钮 |

## 四、已修复的前端问题

1. **首屏无说明** → 新增「开始」页，30 秒内能回答三个问题，并有 6 步演示路径与完成状态。
2. **主入口含糊** → 「加载正式视觉案例（5 篇，含预置分析结果）」成为主按钮；旧 NLP 样例明确标为「开发回归样例 · 仅用于回归测试」。
3. **导航不知所云** → 改为任务顺序 + 可理解名称 + 每步状态点（已完成/待处理/警告/未配置），编号保留为次要信息。
4. **实验比较页过载** → 20 条记录改为紧凑表格，加筛选与搜索；推荐对照常驻；对照卡片上移；完整明细折叠。
5. **状态配色误导** → 修复「正面说明被显示为警告色」；新增状态徽标（颜色 + 圆点 + 文字）与状态图例。
6. **模型未配置占屏** → 压缩为一行，明确「未配置也能完整演示」，并给出两个动作。
7. **缺少下一步** → 首页、论文库、实验比较页均有明确的「下一步」与主/次按钮。
8. **可访问性** → `:focus-visible` 焦点环（Tab 实测 `outline: solid 2px`）；状态不依赖颜色；弹层有「关闭」；窄屏表格在容器内横向滚动，整页无横向溢出。
9. **刷新回到原页面** → 记住上次所在页，避免新用户以为数据丢了。

## 七、仍然会让新用户困惑的地方（如实记录）

1. **推荐对照大多落在「信息不足」**：因为 Swin/ConvNeXt 的部分实验记录缺「蒸馏/测试时增强」等字段，程序如实判「信息不足」。
   这符合规则，但第一次看会以为「系统什么都判断不出来」——目前靠对照表把「哪个字段未知」列出来缓解。
2. **「表格行列待核查」占比高（18/20）**：原因是双栏/跨行排版无法用文字坐标确认列对齐。页面上有原因说明，但对新用户仍偏技术。
3. **阅读决策需要自己填条件**：预置示例已可直接查看，但「按我的条件生成」这一步对不熟悉的用户仍有门槛（页面上已标明需要填什么）。
4. **方法关系图的读图规则**：三档标签有图例，但线型（实线/虚线/点线）与「待核查」的对应关系仍需一句话提示。
5. **语料集切换后的空档**：切换到另一套语料时会短暂显示空状态（数据随加载而来），已用「下一步」提示缓解，但仍可能让人觉得「东西没了」。
