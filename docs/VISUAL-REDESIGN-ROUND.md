## 一、视觉审查：旧版为什么不像一个完成度高的产品

审查方式：对每个页面在 1440×900 与 390×844 下逐屏截图（`docs/ui-audit/` 为旧版证据，`docs/ui-audit-light*/` 为本轮过程记录）。

| 问题 | 具体证据（旧版） |
| --- | --- |
| **首屏没有主任务** | 深色侧栏 + 09 个编号导航；首屏是「开始」页但顶部没有品牌栏，一眼看到的是深色卡片堆叠与两段说明文字 |
| **整体像开发控制台** | 页底色 `#0e1116`、卡片 `#151a22`、边框 `#2a323f`；大面积深色 + 高对比描边，观感偏后台面板 |
| **信息过载** | 实验比较页 5389 字符 / 184 行（20 条记录全部展开成卡片）；开发状态页 1710+ 字符技术信息；论文库顶部有 4 个文本块才出现按钮 |
| **按钮优先级不清** | 论文库同一行出现「重新加载该语料集 / 上传自己的 PDF / 换成开发回归样例 / 用预置结果演示 / 去配置接口」5 个同级按钮；实验比较页有「判断口径与边界 / 清空 / 查看原文 ×N」 |
| **页面职责重叠** | 跨论文比较（论文级）与实验比较（实验级）并列在主导航里，容易被误认为同一件事；「设置 / 状态与记录」与核心研究流程平级 |
| **颜色与字号** | 状态色 `--warn` 同时承担「警告」和「待核查」；正文 12~14px 偏小；卡片圆角 8/10/12 混用；表格两套样式（`.cmp` / `.exp`）不一致 |
| **窄屏最明显的问题** | 侧栏压成横向换行的导航条（每项最小 96px），首屏几乎全是文字；表格需要横向滚动；没有顶栏，品牌与次级入口不可见 |

**修改顺序**（按影响）：① 设计令牌与浅色主题 → ② 顶栏 + 任务流导航 + 面包屑与进度 → ③ 首屏 → ④ 论文库 → ⑤ 实验比较（左筛选/右结论）→ ⑥ 状态语言统一 → ⑦ 窄屏与可访问性。

## 二、视觉方向与设计系统

按 skill 的设计系统（色彩 60-30-10、1.25 字阶、4px 间距网格、阴影层级、中文行高 1.7~1.8）落地：

| 维度 | 取值 |
| --- | --- |
| 背景 | 页面 `#f8f9fb`（暖灰）、卡片 `#ffffff` |
| 文字 | 深墨 `#16202e` / 次要 `#4c5a6e` / 辅助 `#7b8798` |
| 主色 | 靛青 `#4f46e5`（hover `#4338ca`），浅底 `#eef0ff` |
| 警告 | 琥珀 `#b45309`（底 `#fdf3e3`） |
| 待核查 | 橙 `#c2410c`（底 `#fdeee4`） |
| 已核验 | 绿 `#15803d`（底 `#e8f7ee`） |
| 不可比 / 错误 | 红 `#b91c1c`（底 `#fdecec`） |
| 圆角 / 阴影 | 8 / 12 / 16px；`0 1px 2px rgba(22,32,46,.05)` 与 `0 4px 14px rgba(22,32,46,.07)` |
| 动效 | 仅 150ms 的颜色与边框过渡，无装饰性动画 |

**状态视觉语言统一为 7 种**（图标 + 文字 + 颜色，不依赖颜色单独表达）：
`◉ 实时分析`、`▤ 缓存案例`、`✎ 人工修正`、`✓ 已核验`、`! 待核查`、`? 信息不足`、`⟳ 已过期`。
**规则保留**：文本可定位但版面行列未确认 → 一律 `待核查`（橙），绝不用成功绿；`已核验`只用于证据与范围都满足的记录。

## 四、新用户实际操作路径（真浏览器实走，本地 41/41、线上 41/41）

### 路径 A：空状态首次打开
1. 打开页面 → 顶栏品牌与定位；首屏一句主文案 + 两个 CTA + 三步流程；无技术噪声。
2. 点「开始分析视觉论文」→ 演示案例加载完成（导航显示 5 篇）。
3. 进「论文库」→ 案例信息条（5 篇 / ImageNet 图像分类 / 23 条实验记录）、论文方法标签、字段证据、实验条数。
4. 点「查看实验」或「进入实验比较」→ 进入核心工作区。

### 路径 B：正式视觉案例完整演示
1. 实验比较页**默认已给出一组推荐对照**（不需要用户先猜）→ 右侧大结论卡给出档位 + 人话解释 + 具体原因。
2. 展开「查看详细条件差异」→ 逐项条件差异与信息不足项 + 完整条件表（预训练数据 / 分辨率 / 蒸馏 / 测试时增强…）。
3. 点「查看原文证据（…·p.12）」→ 弹层显示页码、原文上下文与定位校验，可关闭。
4. 换一组「口径不同的例子」（ResNet 错误率 ↔ ViT/DeiT 准确率）→ 明确判「不能直接比较」并解释两者可互换但方向相反。
5. 进「方法关系」→ 先看方法演进摘要（5 条，带证据状态），再看关系图与三档标签。
6. 进「阅读建议」→ 阅读顺序与目标匹配（论文证据判断 ≠ 实际运行）。

截图：`docs/demo-walkthrough-v2/`（本地）与 `docs/demo-walkthrough-v2-live/`（线上）。

## 七、本轮的一个真实发现（不属于界面问题）

我在改造实验比较页时统计了预置语料中所有跨论文分类实验对的可比性等级：

| 等级 | 对数 |
| --- | --- |
| 可以直接比较 | **0** |
| 只能结合条件讨论 | **0** |
| 信息不足，不能直接比较 | 48 |
| 不能直接比较 | 112 |

原因有两类，**都是真实的**：
1. ResNet 报 top-1/top-5 **错误率**，其余论文报**准确率** → 指标方向不同，判「不能直接比较」（这类 112 对）；
2. ViT / Swin / ConvNeXt 的若干实验记录缺「蒸馏、测试时增强、单模型/集成」等字段 → 判「信息不足」（48 对）。

因此本轮验收标准里的「查看『只能结合条件讨论』」在当前预置语料中**不可达**。我没有为了让某个档位出现而修改规则或补写数据，而是：
- 保留真实结论，并把「为什么不能比 / 缺哪个字段」直接展示在结论卡与条件表里；
- 增加一个**可达的对照入口**「口径不同的例子」（ResNet 错误率 ↔ 其他论文准确率），用真实数据演示「不能直接比较」；
- 在下一轮建议：重跑 vision 语料的抽取，补齐蒸馏 / 测试时增强等字段（属于模型侧工作，本轮明确不做）。

## 八、仍然不够好看 / 仍需改进的地方

1. **推荐对照的档位偏「信息不足」**：视觉上结论卡是橙色的，第一次看会以为系统没给出答案；已用「具体到这里：两者在『额外数据』上不同…」缓解，但还需要一版更积极的文案。
2. **方法演进摘要与关系图之间仍有重复感**：摘要讲一遍、图上再看一遍，中间缺少「图上这三条线对应摘要里的哪两句」的联动。
3. **论文库的两级操作**：`查看论文` 展开后才看到字段与条件表，展开后的信息密度仍然偏高（7 个字段卡 + 2 张表）。
4. **跨论文比较（论文级）仍是旧样式密度**：它保留了原来的表格与勾选逻辑，只是被降级到「更多」，视觉上没有完全跟上新系统。
5. **状态色在浅色下的对比**：橙色 `#c2410c` 在浅底上对比度足够，但大号数字仍用主文字色，未按状态着色，视觉冲击力偏弱。
6. **顶栏在窄屏会换行**：390px 下品牌 + 两个次级按钮占两行，略显拥挤。
