## 3. 三步引导（完整地图之前）

`.mapguide` 位于 `.mapwork` **之前**，内容是：

```
01 选择方法            02 看一句话回答          03 查看证据与完整对照
先回答一个问题：〔DeiT 相比 ViT 改变了什么？〕〔系统推断〕〔没有绑定引文〕
```

问题来自 `pickExploreRelation()`（与「联系与区别」同一个函数）：按「类型 extends>improves>combines>similar × 证据 原文明示>系统推断>待核查」挑一条，
再交给 `exploreQuestion()` 生成问法——所以 **DeiT / ViT 不是写死的**，换一组语料问法跟着变；一条关系都没有时不做提问（`pickExploreRelation` 返回 null），改为说明「不生成提问，直接点方法节点」。

点问题 = 选中那条连线：两个端点节点高亮、连线变 `hot`（0.75s 短暂加粗）、右侧面板打开，第一行是「一句话回答」，随后「证据状态」。

## 4. 动画

| 动效 | 实现 | 时长 |
| --- | --- | --- |
| 详情面板淡入 + 轻微位移 | `@keyframes mapIn`（桌面）/ `mapInUp`（手机底部抽屉） | 500ms / 450ms |
| 节点选中描边 | `transition: stroke/stroke-width/fill` | 300ms |
| 相关连线短暂高亮 | `@keyframes edgeFlash`（stroke-width 5 → 2） | 750ms，一次性 |
| 三步引导进入视口 | IntersectionObserver + `.reveal/.in`（**不 unobserve**，离开视口移除 `.in`，可反向淡出、可重播） | 450ms |

不自动轮播、无循环动画；`prefers-reduced-motion: reduce` 下全部关闭位移与动画（引导直接显示）。

## 5. 三个必须说明的取舍

1. **分栏数量 = 真实归组结果，不是截图的三栏。** 当前 5 篇论文被 `classifyFamily()` 归成两个家族：
   `卷积网络（CNN）` 2 篇（ResNet / ConvNeXt）、`Transformer 架构` 3 篇（ViT / DeiT / Swin）。
   截图里的「ConvViT / EfficientNet / 混合架构」是虚构示例，本项目不会为了凑三栏而编造家族或节点。`LANE_ORDER` 仍然支持 `cnn / transformer / hybrid / pending` 四类，数据里出现几类就画几栏、篇数动态显示。
2. **语料集显示名改为「视觉方法演进案例」。** 这是唯一改到 `src/core` 的地方——`CORPUS_META.vision.label` 一个字符串（没有任何判定逻辑）。
   同步改了 `App.tsx`（面包屑改用 `scope.meta.label`，不再硬编码）、`Library.tsx` 的切换按钮文案，以及引用了旧名字的 4 个走查脚本断言（`e2e-check` / `verify-collection-scope` / `demo-walkthrough2` / `demo-walkthrough4`）。
   改名动机：地图页的标题与导航项按需求统一叫「视觉方法演进案例」，避免一处叫 A、一处叫 B。
3. **「方法提取」指向现有的「上传论文」页**（该页就是配置模型 → 导入 → 抽取的完整流程）。本项目不新增路由，所以左侧五项全部复用现有页面：
   论文集合 → 论文库、方法提取 → 上传论文、研究地图 → 研究地图、实验可比性 → 全部结果与条件、阅读路线 → 阅读建议。
