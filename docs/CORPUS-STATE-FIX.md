## 一、重复加载的根因（实测确认，共两条）

### 根因 1：历史数据没有语料集身份，且计数来源不一致

- 早期版本的论文/方法**不带 `corpusId`**。恢复数据时它们仍在状态里，但论文库按语料集过滤后**看不见**，
  而左侧数字用的是 `papers.length`（全量）→ 出现「论文库 5 篇」但实际状态里还有另一套 5 篇的情况。
- 再次加载时 `loadSample` 只按「ID 是否已存在」做过滤，**没有按语料集做范围替换**，
  于是新旧记录叠加 → 左侧变成 10 篇；同时实验比较页出现「没有实验记录」但左侧有论文的错位
  （旧方法记录里没有 `experiments` 字段）。

复现证据（`scripts/repro-duplicate-load.mjs` 与 `scripts/verify-corpus-state.mjs`）：
在干净会话里不会重复（5/23/10），一旦注入无 `corpusId` 的历史记录，旧版本就会出现上述叠加。

### 根因 2：论文库的加载按钮把 React 事件当成了参数

论文库里写的是 `onClick={onLoadSample}`，而 `loadSample(key: CorpusKey = corpus)` 会把事件对象当作 `key`，
于是 `CORPUS_META[event]` 为 `undefined`，加载**静默失败**（被 try/catch 吞掉，只写日志）。
表现就是用户看到的「点了加载没反应 / 数量从 5 变 10」这两种混乱行为的来源之一。

## 二、语料集隔离方式（修复方案）

新增 `src/core/corpus.ts` 作为「当前语料状态」的唯一来源：

| 机制 | 说明 |
| --- | --- |
| **稳定语料集身份** | `vision-classification`（视觉论文案例）与 `nlp-dev`（开发回归样例）；用户上传的论文归 `user-import` |
| **稳定论文 ID** | 由 arXiv 编号派生（`p_arxiv_1512.03385`），因此可据此把历史数据归位 |
| **历史数据归位** | 启动时给没有 `corpusId` 的记录补标记（匹配预置 ID → 对应语料；其余 → 用户自传）并写回 IndexedDB |
| **范围计算** | `scopeCorpus(papers, methods, corpus)` 统一算出：预置论文、自传论文、其它语料残留、实验记录数、分类实验数 |
| **统一计数** | 左侧导航、首页、论文库、实验比较、方法关系**全部**改用 `scope.*`，不再直接用全量数组长度 |
| **关系按端点过滤** | `scopeRelations()` 只保留当前语料的方法作为端点的关系 |
| **幂等加载** | 加载前先按语料集删除已有论文/方法（IndexedDB + 状态），再写入索引内容；重复点击不变 |
| **切换 = 替换** | 切换语料集时移除上一套的预置论文与方法（不做叠加）；自传论文不受影响 |
| **加载互斥** | `corpusLoading` 期间按钮禁用；重复点击会明确提示「已忽略本次点击（避免重复写入）」 |
| **失败保留** | 加载失败时保留已有数据，给出「重试加载」动作与失败原因 |
| **旧数据显式处理** | 论文库出现「检测到其它语料集的数据（N 篇）」提示，提供「切换过去」与「清理这些数据」两个动作，不静默合并 |

## 三、修复前后的数量对比（实测）

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 空会话加载一次 | 5 篇 / 23 条（正常） | **5 篇 / 23 条 / 10 条关系**（IndexedDB 也是 5 / 5 / 10） |
| 首页 + 论文库 + 实验比较各点一次「加载」 | 可能 10 篇（叠加）；论文库点击还会静默失败 | **仍为 5 篇 / 23 条**，IndexedDB 未累积 |
| 刷新后再加载一次 | 可能再叠加 | **仍为 5 篇 / 23 条** |
| 存在历史 NLP 数据时 | 混入计数（5 → 10） | **计数仍为 5**；历史记录被标为 `nlp-dev` 并在论文库提示为「其它语料集」，可一键清理 |
| 切换到 NLP 再切回视觉 | 两套并存、计数混乱 | **切换即替换**：NLP 显示 5 篇（其自身语料）；切回视觉仍 5 篇 / 23 条；IndexedDB 只剩当前语料 |

## 五、实验比较页的信息优先级调整

新的顺序（自上而下）：① 当前语料集 + 论文数 + 分类实验数 + **已选 N / 2 条记录** → ② 问题句「这些 ImageNet 结果，真的可以直接比较吗？」
→ ③ 推荐对照（长名称截断，`title` 悬停可看完整名称，并附档位）→ ④ 结论卡（档位 + 一句人话解释 + 「具体到这里」的原因 + 大号数值 + 原文证据主按钮）
→ ⑤ 详细条件差异与完整条件表（折叠）。

状态说明：`信息不足，不能直接比较` 的一句话说人话解释固定在结论卡可见区域，冗长原因（逐条 reasons、caveats、完整条件表）收进折叠区。

## 九、仍未解决 / 需注意

1. **IndexedDB 中不同语料集不再并存**（切换即替换），因此切换后需要重新点一次「加载演示案例」——这是有意为之，避免叠加；预置语料随时可重新加载。
2. 历史数据归位只按「预置 arXiv ID」判定，若用户此前手工导入过与预置同 ID 的论文，会被归到该预置语料（可手动清理）。
3. 实验比较页的推荐对照在当前语料中仍以「信息不足」为主（原因见上一轮报告：ResNet 报错误率、部分记录缺蒸馏/测试时增强字段），本轮未改判定。
