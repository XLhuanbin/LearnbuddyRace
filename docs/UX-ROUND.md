## 二、界面解决了哪些困惑

| 困惑 | 现在的处理 |
| --- | --- |
| 进来不知道从哪下手 | 画布顶部给出具体问题 + 一个主按钮（问题随数据变化，不是写死文案） |
| 点开以后先看到一大堆推断理由，不知道结论是什么 | 详情改为「一句话回答 → 系统推断标签 → 方向 → 具体变化/理由 → 原文依据（折叠）→ 下一步」 |
| 不知道「系统推断」到底能不能信 | 推断说明旁直接写「不是论文原话」；展开原文依据时若没有引文，明确写「没有绑定可核验引文，只作为推断/候选呈现」 |
| 找不到下一步 | 关系详情与节点详情都加了「下一步」区：完整对照 / 看下一条联系 / 比较实验表现（次级） |
| 关系表太长，看不到最有用的对照 | 「联系与区别」把**两方法对照提到长关系表之前**，并默认预置证据最明确的一对 |
| 阅读路线到底是不是按我的条件生成的 | 未配置模型：入口与结果都叫「查看示例路线」，并写明条件未生效；只有真实生成成功才叫「个性化路线（已按你的条件生成）」 |
| 侧栏「10 篇」和案例「5 篇」分别是什么 | 侧栏徽标改为「5 篇案例 · +N 我传的」，页脚写明「案例 5 篇（本语料预置）· 我上传 N 篇」；两种计数不再混在一起（回归脚本断言：注入 2 篇自传论文后徽标为「5 篇案例 · +2 我传的」） |
| 地图节点偏小、留白不均衡 | 节点加大到 232×88、泳道间距 136、画布内边距与标题带加高；桌面与手机均无横向溢出（手机检查 14 项） |

## 三、首页的调整

- **三个段落**：每段只留一句重点（衬线放大到 17–21px）+ 三条极短要点（看到 / 能做 / 得到），删掉了重复的说明句。
- **用真实案例内容替换空白线框**（都标注来源与状态）：
  - 段 01：真实家族分组与篇数（卷积网络（CNN）2 / Transformer 架构 3），来自预置案例的抽取结果；
  - 段 02：真实关系（DeiT 相比 ViT…）+ 证据状态标签（系统推断）与「无直接引文」标注；
  - 段 03：案例自带示例路线的前三步（ResNet → ViT → DeiT）与各自的「重点看」。
- **首屏到第一段的过渡**：CTA 下方一行小字「下面三段，分别说明你会**看到**什么、**能做**什么、**得到**什么帮助。」
- **第三段末尾增加进入案例的入口**：「进入视觉论文案例」+ 「不用上传任何东西，直接看这 5 篇的方法地图」。
- **文案纠偏**：顶栏由「看懂方法差异，判断结果能否公平比较」改为「论文方法梳理 · 关键结论回到原文」；
  侧栏「未配置模型（可用预置结果演示）」改为「未配置模型（只能看示例结果）」，与线上的真实能力一致。
- 首页底部标注改为：内容来自**预置视觉案例**（离线生成、已通过原文定位校验），关系按证据状态标注，不是本次操作触发的实时分析。

## 五、仍受限制的地方（如实说明）

1. **关系证据的厚度不够**：这个案例里 10 条关系，只有 4 条默认可见（都是「系统推断」，没有一条「原文明示」）。
   所以第 3 步的「一句话回答」来自推断说明，没有可打开的引文——这是数据现状，不是界面可以解决的；
   要让它变成「原文明示」，需要模型在全文里检索到指名的继承措辞（或人工核对后标为原文明示）。
2. **推论的精细度受模型输出限制**：回答句直接取自既有推断理由，如果模型当时写得笼统，界面不会补充细节（不编造）。
3. **个性化路线无法在本环境演示**：没有可用模型密钥，所以只能展示「示例路线」这一种真实可达状态；
   「个性化路线」的界面与判定已实现（非缓存即个性化），但没有真实生成成功后的截图。
4. **手机地图仍是横向滑动的泳道**：文字可读、不溢出，但更理想的方案是按家族纵向堆叠（沿用上轮遗留项）。
5. **「关系不明确」的 6 对**默认不画线，只在选项里可显示——避免制造并不存在的联系，代价是图上显得比实际关系少。
