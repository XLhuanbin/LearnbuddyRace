## 3. 问题与修复

### 3.1 是什么问题（已复现）

`src/core/inferenceReadiness.ts` 第 43 / 50 / 56 行的正则**词边界 `\b` 被写成了单个 `0x08` 退格字节**
（全文共 13 个，用 `python -c "print(open(p,'rb').read().count(b'\x08'))"` 可复核）。第 43 行还连带丢了 `\w*` 的反斜杠。

后果：`looksLikeAvailability()` 里「自称提供」「make…available」「可用措辞 + 链接」三条分支**全部变成死代码**，
只剩「产物 + 系动词 available」一条能命中。该模块此前**零测试覆盖**，所以从 09-18 起一直没被发现。

实测影响（真实语料）：

- DeiT：`We provide an open-source implementation of our method.` → 修复前**漏报**
- DistilBERT：`We have made the trained weights available along with the training code in the Transformers 2 library` → 修复前**漏报**

### 3.2 为什么不能只把 `\b` 补回来

直接补回词边界会**引入新的假阳性**：`released` / `open-sourced` 当**形容词**用的句子也会命中「自称提供」分支。
参赛语料里就能复现（ViT 附录）：

```text
Our implementation is based on the open-sourced PyTorch implementation in https://github.com/csrhddlam/axial-deeplab.
our implementation, similar to the open-source implementation, is very slow on TPUs
```

这两句都**不是** ViT 在发布自己的产物。按项目最高优先级（真实性、保守优先），**假阳性比漏报更糟**，
所以修复必须同时加守卫。

### 3.3 实际改法

1. 补回三处词边界与 `\w*`（13 个 `0x08` → 0）。
2. 新增 `CONSUME_VERBS` 守卫：要求**自称主语与发布动词之间不得夹带**「使用 / 比较 / 基于 / 复现」类动词
   （`use|employ|adopt|follow|base|build|compare|similar|rely|leverage|evaluate|adapt|initiali[sz]|warm-start|borrow|reproduc`）。
   - 分支 A（自称提供）与分支 A'（make…available）**检查主语→动词之间的那段文字**；
   - 分支 C（可用措辞 + 仓库链接）**检查整句**。
3. **删除**第三条分支 `SELF && AVAIL_WORDS && (available|released?|open-?sourced?) && URL_RE`：
   它的条件被 C 分支完全覆盖，而它自身不带守卫 —— 正是它把上面那句 ViT 假阳性判成了发布声明。`SELF` 常量随之删除。
4. 同步模块顶部文档口径，把新排除的假阳性写进「明确排除」列表。

### 3.4 顺带发现的遗留项（**未修**，需你定）

**A1b**：ConvNeXt 摘要里 `Code: https://github.com/facebookresearch/ConvNeXt` 仍然漏报。
**原因不在判定规则**，而在共用的 `relationCandidates.findSentenceCandidates()`：它要求候选句 ≥50 字符，
这一句被切出来只有 20 字符（在 `github.` 的点上被切断），整句被丢弃。

这属于**新增识别能力**而非本次损坏修复，且要动共用分句器（会同时影响关系候选），所以没有在本次一起改。
可选做法：在 `findWeightsAvailability()` 内加一条「产物名词 + 紧跟仓库链接」的兜底扫描，**不改共用分句器**。
（注意方向是安全的：当前是**漏报**，界面显示「未找到该论文的发布声明」——偏保守，不是造谣。）
