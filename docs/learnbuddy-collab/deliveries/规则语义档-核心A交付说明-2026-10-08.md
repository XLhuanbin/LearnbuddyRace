## 1. 实际确认存在的问题（先复现、后修改）

用 `.build/repro-probe-rules.mjs`（不提交）在真实函数上复现，**修复前**表现：

| # | 问题 | 复现观察 |
| --- | --- | --- |
| 1 | 未知数据集/指标被当作一致（`compareExperiments`） | 双方 `evalDataset='未知'`、`metricName='未知指标'` 时 `level = **directly_comparable**`，且 `unknowns=[] blocked=[] reasons=[]` —— 两处都不知道，反而被判成「已知条件下可直接比较」。只有一方未知时又会走硬阻断，文案写成「评估数据集**不同**」（其实是未知）。另实测 `canonicalMetricName('未知指标')` 返回 `'未知指标'` 而不是 `'unknown'`，所以双方未知时连归一化都相等。 |
| 2 | 论文数 < 2 时直接采信模型自报的可比性（`applyDivergenceRules`） | `paperIds=['pa']` + 模型自称 `comparabilityLevel='comparable'` → 最终值就是 `'comparable'`；`paperIds=[]` 同样如此。而单篇论文根本不存在「论文对可比性」。 |
| 3 | 没有 `conditions` 时采信模型自报的 `computeReported`（`generateDecision`） | 方法 `conditions: undefined` + 模型自称 `computeReported: true` → 最终 `computeReported = true`，等于让模型自证「论文报告了算力」。 |

## 3. 新增测试（`tests/core.test.ts` 第 29 节，15 项）

- **未知 ≠ 一致**：`canonicalMetricName('未知指标') → unknown`；双方都未知 → `insufficient_info`（且 `unknowns` 标明 `both`）；只有一方未知 → `insufficient_info` 且 `blocked` 为空；指标未知同上一律；**反向保护**：双方已知且确实不同 → 仍为 `not_comparable`；双方都有值且一致 → 仍为 `directly_comparable`（证明没有把正常路径打死）。
- **可比性不采信模型自报**：`paperIds` 为 1 篇 / 0 篇时模型自称 `comparable` → 一律 `'unknown'`；`>= 2` 篇时由程序重算，模型自报的 `comparable` 不生效。
- **`computeReported` 不采信模型自报**：无 `conditions` + 模型自称 `true` → `false`；有 `conditions` 但算力条目未通过校验 → `false`；**算力条目确实 `verified` → 仍为 `true`**（证明没有过度纠正成永远 `false`）。
- **版本一致性（新增的流程保护）**：断言两个预置语料的 `rulesVersion` 与 `RULES_VERSION` 相等。这条在重算之前**如实报红**（缓存 `r3.0.0` vs 程序 `r3.1.0`），重算之后转绿；以后谁升了规则却忘记重算缓存，它会立刻失败。

## 4. 缓存重算（`scripts/revalidate.mjs`，未调用模型）

```text
node scripts/revalidate.mjs --out public/samples-vision
  论文 5 篇，方法 5 个，关系 10 条 → 校验问题 10 → 10；关系状态变化 0 条；分歧种类变化 0 条
node scripts/revalidate.mjs --out public/samples
  论文 5 篇，方法 5 个，关系 6 条  → 校验问题 18 → 18；关系状态变化 0 条；分歧种类变化 0 条
```

**缓存实际变化**（结构化比对，忽略每次重算都会变的 `vi_*` issue id 与时间戳）：

| 变化 | 说明 |
| --- | --- |
| `rulesVersion`: `r3.0.0` → `r3.1.0` | 必须的版本标记 |
| `revalidationNote` 中的规则版本同步 | 必须的说明 |
| **判定结论零变化** | 校验问题数、关系状态、分歧种类、`checkedPairs` 全部不变；`paperIds`/`level`/`quote`/`page`/`claim` 逐项相同 |
| 分歧 `sides[]` 补上 `quoteEvidence` | 见下方「既有漂移」 |

**为什么判定结论零变化**（这是事实，不是省略）：两个预置语料里**本来就没有** `paperIds < 2` 的分歧结论（vision 是 2 篇 / 4 篇，dev 是 2 篇 / 5 篇），也**没有**未知数据集/指标的实验记录（23 条实验记录全部有值；dev 语料 0 条实验记录）。而且实验级可比性是**实时计算、不进缓存**。所以这三项规则改动只影响实时分析路径，对预置结论没有影响 —— 已用结构化比对核验，不是"看起来没变"。

**顺带发现并修正的既有漂移（不是本次规则改动引起的）**：
预置缓存的分歧 `sides[]` 缺少 `quoteEvidence` 字段。该字段自 `327e6be`（第七、八轮）起就会由 `applyDivergenceRules` 写入，但预置缓存此后没有跟着重算，于是 `Divergence.tsx` 依赖的 `s.quoteEvidence?.verified` 取不到值 —— 分歧页会少显示「（原文已定位：p.N）」以及已核验的样式。本次重算把它补上了（`quote`/`page`/`claim` 与旧缓存完全一致，只是补了证据对象）。
**建议**：这不改变任何判定结论，但产品方向在演示前可留意分歧页这几处标注现在会正常出现。

## 6. 是否改变公共类型、缓存结构或版本号

- **公共类型：未变**。`types.ts` 未改动，未增删改任何字段。
- **缓存结构：未变**。`CACHE_VERSION` 仍为 `3`；缓存 keys、数组长度、各字段语义都不变；只有 `rulesVersion` 取值与分歧 `sides[].quoteEvidence` 的补齐。
- **版本号**：`RULES_VERSION` `r3.0.0` → **`r3.1.0`**（规则确实变了，必须升）；`PROMPT_VERSION` 仍为 `v3.0.0`（未动提示词）。
- 因为 `rulesVersion` 与缓存已一致，界面**不会**弹出「规则已变更、旧结论需重算」的过期提示。

## 7. 是否需要核心 B / 产品方向接入

- **核心 B：不需要**。改动都在核心 A 范围内。
- **产品方向：不需要改代码**，但要知道两处界面可见变化：
  1. 实验可比性页：当某条记录的数据集或指标**未确认**时，该维度现在显示为「信息不足，不能直接比较」（并给出「未确认」的原因），不再显示成「数据集/指标不同」这种确定性结论。以前双方都未知时甚至可能显示成「可直接比较」，现在不会了。
  2. 待调查问题（分歧）页：发现的可比性在论文不足两篇时显示为「未知」；分歧页的引文现在会正常带出「（原文已定位：p.N）」。两者都与论文事实更一致。
