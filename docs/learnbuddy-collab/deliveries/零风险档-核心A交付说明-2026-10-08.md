## 3. 修复做法（要点）

**① 页码：未知就是未知。** 只接受「恰好一个数字」的写法（`3` / `"3"` / `"p.3"` / `"第 3 页"`）；出现多组数字（`"3-4"`、`"表3，第5页"`）一律返回 `undefined`，不再靠拼数字猜。
附带把 `toPage` 导出以便单测（与 `parseGpuCount` / `parseExperimentRecords` 的既有做法一致）。

**② 实验记录：**
- 用 `requireArrayOfObjects()` 替换「非对象就 `continue`」⇒ 结构错误**明确失败**（ModelError），与 `client.ts` 的既定契约一致。
- 上限从 `8` 改为 `MAX_EXPERIMENT_RECORDS = 5`（对齐提示词的 4 条分类 + 1 条非分类）。
- **溢出不再静默**：超过上限时保留前 5 条，并把溢出说明挂到第一条记录的核查问题上（`ExperimentRecord` 没有语料级字段），文案写明「模型返回了 N 条…已只保留前 5 条」。

> 这里有一个**需要团队确认的取舍**：我选择「截断 + 可见提示」而不是「直接失败」。
> 理由是硬失败会让「模型多给几条」这种良性偏差直接打断整次分析（离线全量分析尤其怕这个），
> 而截断并在核查问题上写明，既不静默也不炸。若团队更希望严格失败，改一处 return 即可。

**③ 内层数组字段：** 在 `divergenceRules.ts` 与 `analyze.ts` 用既有的 `optionalArrayField`（出现时必须真的是数组）+ `requireArrayOfObjects` / 新增的 `requireStringArray` 做校验。
校验放在 `divergenceRules` **函数内部**而不是调用方，因为该模块同时被实时分析和 `scripts/revalidate.mjs` 复用。
顺带修了同一函数里的同类隐患：`topic` / `explanation` / `commonScope` / `nextAction` 旧实现是 `(raw.x || '').trim()`，模型把这几个标量写成数字时会**直接抛 TypeError**；现统一用 `asStr` 只接受字符串（**不做** `String(v)` 兜底 —— 那会把对象变成 `[object Object]` 之类的假内容）。

**④** 删掉 `extractMethod` 里重复的那一行赋值，未顺带重构任何无关逻辑。

## 4. 新增测试（`tests/core.test.ts` 第 28 节，21 项）

- **页码**：`"3"→3`、`"p.3"/"第 5 页"`、`"3-4"→未知`、`"表3，第5页"→未知`、`0/-2/""` → 未知；以及用户可见后果「`"3-4"` 不再产生虚假 `page_invalid`」。
