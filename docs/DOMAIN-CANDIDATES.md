## 候选一：三维点云中的语义分割（用户曾导入过点云论文，因此列入候选）

| 维度 | 情况 |
| --- | --- |
| 面向什么学生 | 计算机/自动化/测绘方向本科高年级或硕士新生，做三维视觉或机器人感知方向的课程设计、毕设入门 |
| 具体调研问题 | 「在同一评测集（如 S3DIS / ScanNet / SemanticKITTI）上，点云语义分割的方法从 PointNet 到点 Transformer 类方法，性能提升主要来自哪一类改动（采样/邻域聚合/注意力/训练策略）」 |
| 能否找到可比较的论文 | **能，且是本候选的最大优势**：同一任务（语义分割）、同一数据集（S3DIS 6-Fold / Area-5、ScanNet、SemanticKITTI）、同一指标（mIoU/OA）被广泛共用；检索到的方法对照表里经常同时出现多篇论文的同一指标数值 |
| 能否找到有原文依据的方法关系 | **部分已核实**：PointNeXt 的标题/摘要即为「Revisiting **PointNet++** with Improved Training and Scaling Strategies」（继承 + 改进）；PointNet++ 本身是对 PointNet 的分层扩展。摘要层面线索稀少（见 `DOMAIN-RELATION-PROBE.md`：8 篇里只有 1 篇命中），**其余需要在全文中核实** |
| 需要多少背景才能人工核对 | **中等**：需要能读懂 mIoU/OA 的含义、知道 S3DIS 的 6-Fold 与 Area-5 不是同一划分、理解「采样点数/体素大小」会改变可比性。不要求会写点云网络代码 |
| 获取与解析的实际难点 | 论文本身（arXiv）都可下载且有文本层；**难点在数据与代码**：S3DIS/ScanNet 需申请或体积很大，验证「能否复现」基本不现实——这正是系统要如实标「执行可行性」而不是给 suitable 的场景 |

## 候选二：低资源条件下的视觉表征与轻量模型

| 维度 | 情况 |
| --- | --- |
| 面向什么学生 | 本科毕设/课程设计，只有单卡或免费算力（Colab 级），想做「能跑起来」的对比实验 |
| 具体调研问题 | 「在只用单卡、固定轮数的条件下，自监督预训练（SimCLR / MoCo）与轻量架构（MobileViT / EfficientNet）哪条路线在少量标注下的性价比更高」 |
| 能否找到可比较的论文 | **有限**：ImageNet 上的 top-1 可比性较高，但自监督方法的线性探测协议、轻量模型的分辨率/参数量设定差异很大，**「同口径对照」需要仔细挑实验**；本项目会把这类情况判为「只能有限比较」或「信息不足」 |
| 能否找到有原文依据的方法关系 | **中等偏低**：摘要层面只有 MobileViT 命中 1 处线索；这类论文多为平行路线（自监督 vs 轻量架构），**关系更多是「组合/借鉴」而非继承**，可能出现大量「系统推断」而无「原文明示」 |
| 需要多少背景才能人工核对 | **较高**：必须能区分线性探测/微调协议、分辨率与 epoch 对 top-1 的影响，否则很容易把不同口径的数字直接对比 |
| 获取与解析的实际难点 | 论文易得；**算力与数据是硬约束**（ImageNet 需要较大存储与算力），实际执行基本只能做小规模子集实验 |

已核实论文：SimCLR `arXiv:2002.05709`、MoCo `arXiv:1911.05722`、MobileViT `arXiv:2110.02178`、EfficientNet `arXiv:1905.11946`、ViT `arXiv:2010.11929`。

## 候选三：检索增强生成（RAG）中的长文档问答

| 维度 | 情况 |
| --- | --- |
| 面向什么学生 | 计算机/软件方向本科高年级或硕士新生，做 NLP 应用或大模型方向入门调研 |
| 具体调研问题 | 「面向长文档问答，检索器与生成器的组合方式（是否训练检索器、是否端到端联合、如何融合多段证据）如何影响答案的事实性」 |
| 能否找到可比较的论文 | **较好**：NQ / TriviaQA / MS MARCO 等数据集与 EM/accuracy 指标被多篇共用；但生成式评测（事实性、忠实度）缺少统一指标，**这部分只能定性比较** |
| 能否找到有原文依据的方法关系 | **较好**：检索到 3 篇摘要出现「retrieval + 关系措辞」线索（RAG、REALM、Self-RAG，见 `DOMAIN-RELATION-PROBE.md`）；这类论文通常会在相关工作里明确写「我们沿用/不同于 X」 |
| 需要多少背景才能人工核对 | **较低到中等**：只要理解检索-生成两阶段与 EM/accuracy 含义即可；是本项目当前抽取链路最成熟的文本域 |
| 获取与解析的实际难点 | 论文最易得、版式规范、文本层完整；**难点在评测口径**（不同论文的 prompt/上下文长度不同），以及「事实性」缺乏统一量化指标 |

已核实论文：RAG `arXiv:2005.11401`、FiD `arXiv:2007.01282`、REALM `arXiv:2002.08909`、RETRO `arXiv:2112.04426`、Self-RAG `arXiv:2310.11511`。

## 推荐（供决策，非结论）

| 排序 | 候选 | 理由 | 主要风险 |
| --- | --- | --- | --- |
| 1 | **候选一 三维点云语义分割** | 同一任务 + 同一数据集 + 同一指标被高度共用，**比较与分歧最有内容**；执行可行性天然是「已知存在资源差距」，正好体现本作品「分别表达目标匹配与执行可行性」的价值；也承接你之前导入的点云论文 | 数据/代码获取难度高；方法关系需要全文核实（摘要信号弱） |
| 2 | **候选三 RAG 长文档问答** | 抽取链路最成熟（纯文本、版式规范），关系线索在摘要里已可见 | 「可比性很强」的论文反而不多，事实性口径不一致；与当前 5 篇同属语言模型域，**领域差异度不如候选一** |
| 3 | 候选二 低资源视觉表征 | 贴近「单卡学生」的真实处境，目标匹配容易讲清楚 | 可比性最弱（协议差异大），可能大量结论落成「信息不足」，展示效果不如前两个 |
