## 1. 先复现

`.build/availability-audit.mjs`（不提交）跑两个预置语料：

```text
- p_arxiv_2201.03545 A ConvNet for the 2020s
  found = false                     ← ConvNeXt 漏报（语料里其余 9 篇都有结论）
```

**根因不是判定规则**：`findWeightsAvailability` 依赖共用的
`relationCandidates.findSentenceCandidates()` 分句，后者以句点切分并要求候选句 **≥50 字符**；
ConvNeXt 摘要里那句 `Code: https://github.com/facebookresearch/ConvNeXt` 会在 `github.` 的点上被切断，
切出来只有 20 字符，被 `if (text.length < 50) continue` 整句丢掉。所以句子级检索永远看不到它。

（同一原因也解释了为什么它没法靠 `prompts.ts` 或模型侧解决：这一行是**确定性全文检索**，不经过模型。）

## 2. 复现时先把「误判风险面」摸清

我把两个语料里**所有** `github.com / gitlab.com / huggingface.co` 出现的上下文逐条打印出来核对，结论：

| 形态 | 例子（真实语料） | 该不该认 |
| --- | --- | --- |
| 目标：产物 + 冒号 + 仓库 | `Code: https://github.com/facebookresearch/ConvNeXt` | ✅ 认 |
| 参考文献条目 | `[80] Ross Wightman. GitHub repository: Pytorch image models. https://github.com/rwightman/pytorch-image-models, 2019.` | ❌ 不认 |
| 参考文献条目 | `[3] GitHub repository: Swin transformer for object detection. https://github.com/SwinTransformer/…` | ❌ 不认 |
| 参考文献条目 | `[2] GitHub repository: Swin transformer. https://github.com/microsoft/Swin-Transformer, 2021.` | ❌ 不认 |
| 脚注里的纯链接 | `11 https://github.com/openai/gpt-3/blob/master/overlap_frequency.md` | ❌ 不认 |
| 数据集链接（别人给的） | `Data can be found at https://github.com/mcdm/CommitmentBank/` | ❌ 不认 |
| 论文在说别人的产物 | `Our implementation is based on the open-sourced PyTorch implementation in https://github.com/…` | ❌ 不认（A1 已挡） |

关键观察：**「认」与「不认」在字符层面就分得开** —— 参考文献条目里的产物名词与链接之间都隔着句号等字符，
而目标形态是「产物 + 冒号 + 链接」紧邻。所以兜底可以做得非常窄。

## 3. 改法（只在 `inferenceReadiness.ts` 内部）

新增 `ARTIFACT_THEN_REPO` 与 `findCompactDeclaration()`，并在**句子级检索落空之后**才调用：

```text
产物名词（codebase|code|models?|checkpoints?|weights?|implementations?|libraries?）
  → 冒号 [:：]（要求必须有，见下）
  → 可选 https:// / www.
  → 仓库主机（github.com | gitlab.com | huggingface.co）
  → 可选的路径尾巴
```

三条设计决定，都写进了代码注释：

1. **只认紧邻**：产物名词与链接之间除空格/冒号外不允许有别的内容 —— 参考文献条目全部被这一条挡掉。
2. **刻意要求冒号**：`Code https://…`（无冒号）不认。因为参考文献里确实存在省略句点的写法
   （`Pytorch image models https://github.com/…`），有冒号才能把它们排除；代价是漏掉极少数无冒号写法，
   按「宁可漏报也不误报」取舍。
3. **故意不加窗口级否定判断**：`Code is not available at https://…` 已经被紧邻要求挡掉；反过来，
   若按窗口查否定，「本文没有在 PyPI 上提供。Code: https://github.com/…」这种同段含无关否定的**真声明**会被误杀。
   残余风险只剩「同一短语里既否定又给链接」的自相矛盾写法。

**没有改共用分句器**（`relationCandidates.findSentenceCandidates`）：它同时服务关系候选抽取，
放开长度下限或切分规则会波及其它判定，风险远大于收益。兜底结果同样必须过 `buildEvidence` 的定位校验，
定位不到就不算 —— 与其它证据同一套口径（所以页码仍是程序算出来的，不是模型自报）。

**顺序**：句子级优先，兜底只在句子级落空时使用，保证已有 4 篇的「上下文更完整」的证据句不被改写。

## 6. 版本号与缓存影响（按要求实查，未默认跳过）

| 项 | 结论 | 依据 |
| --- | --- | --- |
| `PROMPT_VERSION` | **不需要动** | 提示词文本一字未改；本次是确定性全文检索的识别能力，不经过模型 |
| `RULES_VERSION` | **不升**（建议） | 它管的是「缓存里的**判定类结论**在当前规则下是否仍有效」（可比性 / 关系校验 / 条件范围 / 证据支持判定）。本次改的是**检索能力**（多认一种写法），不改任何判定口径；`revalidate.mjs` 也不重算该函数的产物。若升版本，唯一效果是让缓存里的关系被要求重判，与本次改动无关 |
| `CACHE_VERSION` | **不需要动** | 缓存结构未变 |
| 预置缓存 | **需要重算 `decisionSample`（仅 vision）** | 见下 |

`findWeightsAvailability` 的结果会被 `generateDecision` 写进"推理可行性"那一行，而**示例决策是缓存的**、
且 `App.tsx` 载入预置语料时直接用它当阅读路线（`App.tsx:728` `setPlan({ ...index.decisionSample, cached: true })`）。
我用 `.build/compare-sample-availability.mjs`（不提交）把**示例里的那一行**与**当前实时结论**逐条对齐：

```text
public/samples-vision（参赛案例）
  p_arxiv_1512.03385 ResNet      实时 false ｜ 示例「未检索到」 → 一致
  p_arxiv_2010.11929 ViT         实时 true  ｜ 示例「可获取」   → 一致
  p_arxiv_2012.12877 DeiT        实时 true  ｜ 示例「未检索到」 → ★ 过期
  p_arxiv_2103.14030 Swin        该行由算力条目决定，与可获取性无关
  p_arxiv_2201.03545 ConvNeXt    实时 true  ｜ 示例「未检索到」 → ★ 过期（本轮 A1b 造成）
public/samples（NLP 开发回归样例）5 篇全部一致
```

- **DeiT 那一行自 A1（`a451d0a`）起就已过期**：A1 修好「自称提供」分支后，DeiT 实时就能命中
  `We provide an open-source implementation of our method.`，但示例里仍写着「全文未检索到」。
  **这是我上一轮漏检的**（当时只说明了实时行为变化，没查示例缓存），在此明确更正。
- **重算方式与代价**：`node scripts/analyze.mjs --decision-only --out public/samples-vision`。
  它**会调用一次模型**（重建候选 / 理由 / 阅读顺序等**模型文案**，不只是程序段），因此会改动示例里由模型产出的文字；
  本环境当前确实有 `DEEPSEEK_API_KEY` 可用（长度 35）。
- **我没有执行**：示例决策属于**演示材料**，且本轮明确要求「不修改产品材料」；重写它的模型文案会花掉你的算力额度、
  也可能改掉 PPT/视频里引用的措辞，这个决定该由你来做。
- 也可以选择**不动**：示例只是「预置样例」，界面对缓存示例有 `cached` 标记；但评委若点开预置案例的阅读路线，
  ConvNeXt/DeiT 那两行会显示「未检索到」，与实时分析不一致 —— 建议在演示前重算一次。
- 注意 `revalidate.mjs` **不覆盖** `decisionSample`（它只重算 methods / relations / divergences / checkedPairs），
  所以「重算缓存」这件事只能走 `--decision-only` 或整体 `analyze`。
