## 第 1 项 · 关系装配：越界端点 / 自环 / 端点缺失不再静默丢弃

**复现**（`.build/probe-relation-skip.mjs`）：`assembleRelationsFromModel` 遇到这三类直接 `return`，
三种情形实测 **issues 都是 0**，读者只看到「关系变少了」，无从判断是模型漏判还是被程序剔除。

**改法**：关系仍然不进入结果，但通过**既有问题机制**留一条可读说明 ——
`ValidationIssue{ scope: 'relation', code: 'parse_warning', severity: 'warn' }`，
`message` 分三种情形写明原因（自环 / 缺少关系端点 / 端点不在本次分析范围内），
`action` 给出「确认范围后重新分析，或人工添加该关系」。
`parse_warning` 这个码此前**已声明但从未使用**，正是这类装配告警的位置。

**刻意保持静默的只有一处**：同一对端点的重复行归并 —— 那只是归一化，关系本身仍在结果里，没有信息丢失。

**缓存影响：无（已先确认）**。核实结果：关系问题只进**分析日志**（`App.tsx` 的关系分析日志、离线管线的计数与报告），
缓存里的 `relations` 项没有 `issues` 字段、`index` 也没有 `relationIssues` 键 ⇒ 不升版本、不重算。

## 第 3 项 · 实验记录缺 `metricValue` 时仍可能被判「可直接比较」

**复现**（`.build/probe-metric-value.mjs`）：记录没有 `metricValue` → 落成 `''`，**没有任何核查问题**；
- 两条都没有数值 → `compareExperiments` 返回 **`directly_comparable`**（unknowns/blocked/reasons 全空）；
- 只有一方有数值 → 同样 `directly_comparable`；
- 数值写成「未知」「—」「n/a」占位 → 同样被判可比。

**改法**：
- `experiments.ts` 新增 `isMetricValueMissing()`（空串与「未知 / 未给出 / n/a / — / –」等占位都算缺失），
  `compareExperiments` 把它计入 `unknowns`（label「指标数值」）⇒ 级别降为 `insufficient_info`，
  理由写明「没有数字谈不上可直接比较」；位置在硬阻断之后、其它差异之前，因此「缺数值 + 条件不同」也仍是信息不足。
- `analyze.parseExperimentRecords` 同步在**记录级**留下核查问题「未给出指标数值…该记录不参与数值对照」。
- `RULES_VERSION`：`r3.1.0` → **`r3.2.0`**（可比性判定口径变了，必须升）；`PROMPT_VERSION` / `CACHE_VERSION` 未动。
- 按纪律重算两个预置语料（`scripts/revalidate.mjs`，**未调用模型**）。

**缓存变化（结构化比对）**：`vision` 与 `dev` 的**语义差异均为 0** —— 校验问题 10→10 / 18→18，
关系状态 0 变化、分歧种类 0 变化；实际变化只有 `rulesVersion` 与重算时新生成的 `vi_*` id / 时间戳。
原因已核实：两个语料里 **23 条实验记录全都有数值**，而且实验级可比性是**实时计算、不进缓存**。
（重算保留了我上一轮重写过的 `decisionSample`，比对显示它未被扰动。）
