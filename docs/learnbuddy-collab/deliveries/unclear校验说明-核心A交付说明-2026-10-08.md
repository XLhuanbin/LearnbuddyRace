## 3. 为什么要动 `types.ts`（请评审重点看这一条）

先说清楚：**这一条超出了「只修 validateMethod」的字面范围**，我做了但把理由写在这里，方便一行回退。

界面渲染校验问题时，除了长说明，还会显示**校验码的短标签**（`Library.tsx` 用 `ISSUE_CODE_TEXT[v.code]`，
`SettingsView` 也按 code 汇总）。如果继续复用 `evidence_missing`，这一行会变成：

```
未提供引文  ｜  模型提供了原文引文，但自己标注为无法确认…
```

短标签与长说明自相矛盾 —— 等于没修。所以把 `evidence_unclear` 作为**纯新增**的码加进去：

- 只在 `IssueCode` 联合类型与 `ISSUE_CODE_TEXT` 各加一行，**不改动任何既有码的含义与文案**；
- `IssueCode` 在仓库里只有这三处引用（联合类型、`ISSUE_CODE_TEXT`、`ValidationIssue.code`），没有别处的
  `Record<IssueCode, …>` 或 `switch`，加码不会漏改；
- 旧缓存里的 `validation` 数组仍全是旧码，读取与展示都不受影响；新码只会出现在**新抽取**的结果里；
- 若团队坚持不动 `types.ts`，回退方式是把 `validate.ts` 里的三元判断去掉、统一用 `evidence_missing`——
  长说明仍会正确，只是短标签又会变成「未提供引文」。

## 4. 区分机制（不动公共类型）

`MethodFieldResult` 只有 `value / status / evidence / note / claimedPage / userCorrected` 六个槽，
没有可以承载「模型给了引文但自认无法确认」这一区别的字段（不改公共类型的前提）。沿用本仓库既有的做法
（`validate.ts` 早就按 note 里有没有「未报告」/「片段」来区分缺失类型），改为用 note 里的**判据词**：

- 判据词常量放在 `rules.ts`（`validate.ts` 与 `analyze.ts` 都已从它取东西）—— 放 `types.ts` 会把内部文案判据塞进公共契约，
  放 `analyze.ts` 会让 `validate ↔ analyze` 循环依赖；
- `extractMethod` 保证 unclear 的 note **一定含**该判据词（模型自带 note 不含时补一句「（模型标注为无法确认）」），
  避免判据随模型文案漂移（第 1 节情形 ②）。

## 5. 修复后的文案（同一探针复跑）

```text
① unclear（默认 note）
   校验码 [evidence_unclear]
   「核心思路：模型提供了原文引文，但自己标注为无法确认该内容是否支撑结论，因此没有把它作为可核验证据（标记为「未找到证据」）。」
   建议：「这不是「没有给引文」，而是模型自报「找到的文字不足以支撑结论」；需人工回到原文判断该内容能否使用。」

② unclear + 模型自带 note（'只有局部实验描述'）
   字段 note 变成「只有局部实验描述（模型标注为无法确认）」，校验码同为 evidence_unclear

③ 对照组：模型压根没给引文
   校验码 [evidence_missing]，文案与建议**保持原样**
```

**本轮决定保持不变**：unclear 仍按 `no_evidence` 处理、**不挂载**已核验引文（新增测试里有一条专门断言这点）。

## 6. 新增测试（`tests/core.test.ts` 第 31 节，12 项）

- **unclear**：校验码是 `evidence_unclear`；说明**不含**「没有提供任何原文引文」；说明写清「提供了原文引文 + 无法确认」；
  建议写清「这不是没有给引文」；新码在 `ISSUE_CODE_TEXT` 里有标签。
- **对照组**：确实没给引文 → 仍是 `evidence_missing`，文案照旧；note 里没有判据词时**不会**被误判成 unclear。
- **端到端**（mock 模型服务）：`status:'unclear'` → `evidence_unclear`；带模型自带 note（不含判据词）→ 仍被判成 `evidence_unclear`；
  且仍不挂载已核验证据、状态仍是 `no_evidence`。
- **不回归**：可核验字段不产生 `evidence_missing`/`evidence_unclear`；引文无法定位仍是 `evidence_not_located`。
