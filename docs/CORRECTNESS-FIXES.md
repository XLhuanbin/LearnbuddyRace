## 一、比较页与分歧页结论不一致

### 根因

`pairLevel` / `differingDimensions` 复用了「**全集维度结论**」：它们取的是 5 篇论文一起算出来的维度等级，
再按论文对挑最差的一档。于是当全集里有论文（Attention Is All You Need）与其它论文的数据集/指标毫无交集时，
该维度在全集层面就是「不能直接比较」，连带把 BERT↔RoBERTa 也判成「不能直接比较」；
而比较页只选了 2 篇、独立调用 `compareConditions` 得到「只能有限比较」。两页口径不同，结论自然冲突。

不是缓存过期，也不是模型生成了判定 —— 分歧页的 `checkedPairs` 确实来自离线缓存，但冲突的真正原因是**计算口径不同**。

### 修复

1. 新增 `comparePair(papers, methods, a, b)`：按论文对**重新计算**。
   `pairLevel` / `differingDimensions` 改为内部调用它，不再复用全集结论。
2. 分歧页的「已检查的论文对」改为在**渲染时实时重算**（`useMemo` + 同一个 `pairLevel`），不再展示缓存里的旧结论。
3. 离线分析里生成 `checkedPairs` 也改用同一个 helper（`buildCheckedPairs`），消除第三套实现。
4. 缓存绑定版本：`index.json` 新增 `rulesVersion` 与 `inputsSignature`；加载时由 `assessCorpusStaleness`
   比对「规则版本 / 提示词版本 / 输入论文集合」，不一致即标为过期并在界面提示。
5. 缓存格式版本不一致不再直接抛错（旧结构由 `migrateMethod` / `migrateRelation` 迁移），避免线上因版本号变化而完全加载失败。

### 修复前后（真实样例）

| 论文对 | 修复前（分歧页） | 修复前（比较页） | 修复后（两页一致） |
| --- | --- | --- | --- |
| BERT ↔ RoBERTa | 当前不能直接比较 | 只能有限比较 | **只能有限比较** |
| BERT ↔ DistilBERT | 当前不能直接比较 | — | 当前不能直接比较 |
| Attention ↔ BERT | 当前不能直接比较 | — | 当前不能直接比较 |

另外把总体结论的聚合优先级改为：**不能直接比较 > 信息不足 > 只能有限比较 > 可以直接比较**。
理由是只要有关键维度未知，就不能声称「可以有限对照」。因此 BERT↔RoBERTa 在「额外训练数据/数据划分未知」的情况下，
逐维度仍显示「数据集：只能有限比较、实验设置：可以直接比较」，总体按更保守的一档给出。

## 二、额外训练数据的证据范围错误

### 根因

1. 只有一个 `extraTrainingData` 维度，把「预训练语料」「下游额外训练数据」「数据增强」混在一起；
2. 只要引文能定位，就把该条目判为 `verified`，**没有检查引文是否支撑主张**。
   RoBERTa 的条目取到的是局部实验/表格描述，却被当成「整篇论文没有额外训练数据」；
3. 判定一致性时只看取值是否相同 —— 两篇都写 `none` 就判「完全一致」，**没有区分「论文级结论」与「某次实验的描述」**；
4. `dataSplits` 把不同数据集的划分当成同一条件比较（BERT 的 CoNLL-2003 划分 vs RoBERTa 的 GLUE 划分）。

### 修复

1. 维度拆分：`pretrainingCorpus`（预训练语料）/ `downstreamExtraData`（下游额外训练数据）/ `dataAugmentation`（数据增强）分开；
   新增 `scope`（paper / experiment）与 `scopeDetail`（哪个任务/数据集/表），算力条目另加 `stage`（预训练/微调/推理）。
2. 条件状态细分为五态：`verified` / `unverified`（引文不支撑主张）/ `not_reported`（论文明确没有）/ `not_extracted`（本次片段中未提取到）/ `unclear`。
3. 新增 `assessClaimScope`：局部实验标记（on dev、single model、w/o data augmentation、for each task…）出现时，
   否定式结论不能作为论文级结论 → 状态降为 `unverified` + 仅限某实验，并新增校验问题码 `evidence_scope_mismatch`。
4. 判定一致性时：**任何一篇在该维度不可用（未提取到/无法确认/引文不支撑主张），该维度一律判为「信息不足」**，
   取值相同不再等于条件一致；`downstreamExtraData` / `dataAugmentation` 若缺少范围信息，同样按信息不足处理。
5. `dataSplits` 要求按「数据集：划分说明」书写，比较时**只比较双方都有的数据集**；没有共同数据集则判「信息不足」，
   并在依据中说明「属于不同实验的划分，不能当作同一条件」。
6. 报告新增精度声明 `precision: 'paper-level-screening'` 与固定提示：
   「本判断基于论文级条件汇总，属于初筛；结果级比较需要选定具体实验（任务 + 数据集版本/划分 + 指标 + 实验设置）」。

### 修复前后（真实样例，BERT↔RoBERTa）

| 维度 | 修复前 | 修复后 |
| --- | --- | --- |
| 额外训练数据 | 三篇均为 `none` → **可以直接比较（完全一致）** | **信息不足，无法判断**（条目来自早期结构迁移，缺少适用范围；RoBERTa 的引文是局部实验描述，已标 `evidence_scope_mismatch`） |
| 数据划分 | 把 BERT 的 CoNLL-2003 划分与 RoBERTa 的 GLUE 划分并列比较 | **信息不足，无法判断**（未绑定数据集，无法确认是否同一实验） |
| 评级精度 | 未声明 | 明确标注「论文级初筛，需选择或补充具体实验」 |

## 三、方法关系校验理由与原文矛盾

### 根因

1. 别名匹配用的是**整个方法名字符串**做正则：
   BERT 的方法名被抽取为 `BERT (Bidirectional Encoder Representations from Transformers)`，
   而引文里只写了 `BERT`，整串匹配失败 → 判定「没有出现被继承方法的名称」，与原文矛盾。
2. 反向问题：`GENERIC_TERMS` 曾把 `transformer / bert / gpt` 当成泛化词，
   导致「引文里明明写了 BERT」也会被判成「只提到泛化词」。
3. 判定条件过宽：只要引文可定位、且含引用标记就算「原文明示」，
   于是 BERT→DistilBERT 用「更大 Transformer + (Vaswani et al. [2017])」这种**只支持 Transformer 关系**的片段被认证为 BERT 关系。

### 修复

1. 新增 `methodAliases`：从「简称（全称）」中拆出别名（含括号内外内容），匹配时用词边界正则；
   `GENERIC_TERMS` 只保留真正泛化的词（model / network / architecture / approach…），方法专名不再当作泛化词。
2. 新增 `assessRelationEvidence`，明确「原文明示」必须同时满足：
   - 引文**指名被继承方法**（含简称/全称别名）；
   - 且具备对应关系类型的措辞（extends：based on / build on / extends…；improves：improve / outperform / 指出原方法不足…；similar：需同时提到两端）；
   - **只有引用标记、或只提到更泛的技术名称，不足以认证具体端点**（引用标记不能替代「指名」）。
3. 降级理由改为准确描述「查到了什么、缺什么」，并明确「降级不代表系统断言关系不存在」。
4. 数据模型支持多片段：`Relation.evidenceList`（本次定位到的全部片段）+ 模型输出新增 `quotes` 数组（最多 3 条），
   程序优先挑选「确实能认证该关系」的那一条作为主证据，其余片段供人工判断。
   证据分摊在不同片段时（一个片段有名字、另一个片段有措辞）判为「系统推断 / 待核查」，不升级为原文明示。

### 修复前后（全部 7 条关系，真实样例）

| 关系 | 修复前 | 修复后 | 修复后的理由（与原文一致） |
| --- | --- | --- | --- |
| BERT → RoBERTa（改进） | 待核查；理由「**没有出现被继承方法的名称**」（与原文矛盾） | 待核查 | 「引文提到了被继承方法「BERT」。缺少能说明「改进」的措辞（如 improve / outperform / 指出原方法不足）。」 |
| BERT → DistilBERT（继承） | **原文明示**（证据只提到 Transformer 与 Vaswani et al.） | 待核查 | 「引文没有提到被继承方法（已按简称/全称/括号别名匹配）；含引用标记「[2017]」。缺少「被继承方法名称」这一必需条件，仅凭引用标记或更泛的技术名称不能认证该端点。」 |
| Attention → BERT | 系统推断 | 系统推断 | 无明确陈述 → 保持推断 |
| 其余 4 条（unclear / similar） | 系统推断 | 系统推断 | 保持推断（无明确陈述片段） |

修正后的可信度分布：**原文明示 0 条、系统推断 5 条、待核查 2 条**。
「原文明示」归零是因为按新标准，现有 5 篇论文里没有任何一条被模型选中的片段同时满足「指名被继承方法 + 恰当措辞」。
不为了「明示关系更多」而放宽标准 —— 需要重新生成关系分析（新提示词要求给出最多 3 条候选片段）才可能出现达标片段。

## 四、方法推荐混用预训练与微调成本、引用不支持理由

### 根因

1. `generateDecision` 给每条「依据论文」的理由挂证据时，**只取 `coreIdea` 或 `methodName` 的引文**，
   于是「算力门槛」的理由被挂上了介绍双向表示的摘要句 —— 证据与理由无关；
2. 条件里只有一个 `computeResources`，没有区分这段算力是**预训练**还是**微调**，
   导致「BERT 微调 1 小时 TPU」与「RoBERTa/DistilBERT 的预训练成本」被放在一起比较。

### 修复

1. 算力条目新增 `stage`（pretrain / finetune / inference / from_scratch / distill / unknown）与 `scopeDetail`（模型配置与任务）；
   提示词要求「引用算力时必须说明对应阶段」，材料里也把阶段显式传给模型。
2. 理由新增 `evidenceRef`（模型必须声明依据哪个字段或条件维度），证据**由程序按指向挂载**：
   - 指向 `condition:computeResources` → 挂算力证据，并带上阶段标签；
   - 指向 `field:coreIdea` / `condition:datasets` 等 → 挂对应证据；
   - 未声明依据、或指向的条目没有通过校验的引文 → 标记 `evidenceMissing`，界面显示「该理由没有可核验的证据支持」，**不再展示无关引文占位**；
   - 理由文本里出现 GPU/TPU/小时/天 等资源字样但未指向算力条件 → 同样判为证据不匹配。
3. 决策页每条理由的证据展示改为**完整引文 + 页码 + 章节 + 可点击的完整上下文**入口（调用统一的证据弹层）。
4. 界面把该字段标注为「**模型自述**的条件敏感性（未经验证）」，不再暗示这是已验证结论。

> 说明：受影响的具体推荐文字需要重新调用模型才能更新；本轮先修通用逻辑与提示模板（已完成）。
> 现有预置决策样本按旧提示词生成，已在界面标注为过期，不作为当前结论。

## 六、本轮如何改动受影响数据（未调用模型）

新增 `scripts/revalidate.mjs`：把新规则应用到**已有缓存**上，重算「判定类结论」。
它**不调用任何模型**，不改写模型给出的字段值、引文与理由文字。

| 项目 | 重算前 | 重算后 |
| --- | --- | --- |
| 校验问题 | 8 条 | **30 条**（新增 `condition_structure_migrated` 12、`condition_not_extracted` 7、`evidence_scope_mismatch` 2、`evidence_not_located` 1） |
| 关系可信度 | 原文明示 1 / 系统推断 5 / 待核查 1 | **原文明示 0 / 系统推断 5 / 待核查 2**（1 条降级 + 理由更正） |
| 分歧种类 | 2 条「共同提到的局限」+ 1 条「未发现」 | **2 条「各自局限（无共同对象）」+ 1 条「未发现」** |
| 额外训练数据 | 三篇 `none` → 可直接比较 | 信息不足（引文范围不支撑 + 结构迁移） |

写入 `index.json` 的标记：`rulesVersion: r3.0.0`、`inputsSignature`、`revalidatedOnly: true`、`revalidationNote`（明确写出「模型输出仍来自提示词 v2.1.0 的那次调用，未重新调用模型」）。

**来源区分（三种结果在界面上的呈现）**：
- **规则重算结果** —— 实时由程序在浏览器端计算（可比性、关系可信度、分歧种类、条件一致性），不受缓存新旧影响；
- **模型输出（旧提示词 v2.1.0）** —— 字段值、条件取值、推荐文字；因提示词已升到 v3.0.0，界面统一标注「已标记为过期，不作为当前结论」；
- **人工修正** —— 仍然单独记录（`userEdited` / `overrides`），与上面两者区分，且规则重算不会覆盖人工修正。
