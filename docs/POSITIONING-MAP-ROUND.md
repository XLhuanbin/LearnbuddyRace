**定位纠偏（依据最初的《LearnBuddy开发交接.md》）**：主赛题是**论文方法梳理智能体**——批量文献解析、方法分类、
技术演进梳理、有证据支撑的阅读路线与待调查问题；方法关系图与个性化阅读导航是附加能力。
「两个实验分数能不能直接比较」属于**方法对照里的一项能力**，不再作为首页主题与默认主结论。

## 一、新首页定位和主流程

| 位置 | 文案 / 行为 |
| --- | --- |
| 主标题 | **把一组论文，变成你看得懂的研究地图。** |
| 副标题 | 看懂各类方法解决了什么、彼此如何发展，以及你应该先读哪篇。关键结论都能回到原文。 |
| 三个关键词 | 看懂方法差异 · 理清技术关系 · 决定先读什么 |
| 示意图 | 一组论文 → 方法分组与关联 → 阅读路线（页面明确标注「上图为功能示意，非真实分析结果」） |
| 主按钮 | **体验视觉论文案例**：加载现有正式视觉案例并**直接进入研究地图**（不再经过只有一个选项的案例选择页） |
| 次按钮 | **上传我的论文**：进入明确的上传流程，需要模型接口时就地提示配置 |
| 首页不显示 | 论文数量、实验记录数、版本号、API 配置、缓存说明、开发状态、技术规则 |

**主流程**：首页 →（体验案例｜上传论文）→ **研究地图**（三个视图共用同一组论文与选中状态）→ 需要细节时进「更多」。

导航只有三项：**首页 · 研究地图 · 更多**（共 3 个一级入口，不再有七八个页面）。

## 二、三个视图分别给用户什么结果

| 视图 | 回答的问题 | 给用户的结果 |
| --- | --- | --- |
| **看懂方法** | 这组论文主要在研究什么？有哪些不同思路？ | 领域概览（系统汇总，来自已抽取字段）+ 方法分组（卷积网络 / 视觉 Transformer …）+ 逐篇方法卡片：**解决什么问题 · 核心做法 · 与其他方法最明显的区别**；点开才看局限、核心思路全文与原文依据 |
| **联系与区别** | 这些方法如何关联？到底有什么不同？ | 关系图例（原文已说明 / 系统推断 / 待确认）+ **只含真实关系的**关系表（起点 → 关系 → 指向 + 证据状态 + 原文依据）+ 独立节点说明；**发表顺序时间线**（明确标注不代表继承）；选两个方法 → 解决什么问题 / 核心思路 / 主要局限 / 数据集 / 指标对照；**「比较实验表现」是可展开的下一步**（复用实验级比较与条件检查，保留待核查状态） |
| **从哪里开始** | 结合我的目标，应该先读什么？ | 首次只问**基础**与**目标**；选到复现/微调/训练才展开时间与算力（单纯阅读不被预训练算力门槛阻断）→ 给出**建议先读的论文、推荐顺序、每篇重点、简短理由**与「查看依据」；有证据时再列少量待调查问题 |

工作区顶部固定显示：**论文集合名称 · 领域 · 论文数 · 关系数 · 缓存/实时**，以及**添加论文 / 更换案例 / 重新加载案例**
（论文管理与案例切换是工作区的普通操作，不再叫「开发者功能」）。

## 三、复用了哪些能力 / 新增了哪些必要部分

**直接复用（未改动核心逻辑）**：PDF 解析、七字段方法抽取、原文证据与定位校验、方法关系数据（方向与证据状态原样）、
实验级比较与条件核查、阅读建议（profile + steps）、分歧/待调查问题、证据弹层、语料集隔离与幂等加载、缓存/待核查状态语言。

**新增的必要部分**：
1. `src/core/grouping.ts`——**方法归组与领域概览的程序派生**。
   规则按「方法名称 + 核心思路」的关键词归组（卷积 / Transformer / 蒸馏训练策略），
   命中不了的进「暂未归类」；每个分组都带 `basis`（命中的关键词与来源字段）；
   概览只汇总真实字段（论文数、共同数据集、指标、组数、关系条数、缺失字段数），并标注「系统归组」。
   **没有按论文 ID 硬编码任何结果**，随语料变化自动重算（新增 10 项单元测试）。
2. 三个视图组件（`MapMethodsView` / `MapRelationsView` / `MapStartView`）与工作区容器 `MapView`；
3. `UploadFlowView`——上传自己的论文流程（含就地模型配置、处理进度、单篇提示）；
4. 首页 `LandingView` 重写（新定位与示意图）。

**没有新增**：论文质量总分、排行榜、评分系统、失败经验库、全网检索、模型训练功能。

## 四、时间线与技术关系误导是否消除

**已消除**。此前的方法演进页把按年份排序的相邻方法用箭头连成一条线（ResNet→ViT→DeiT→Swin→ConvNeXt），
看起来像继承链，但其中 ViT→DeiT、Swin→ConvNeXt 有证据，而 **ResNet→ViT、DeiT→Swin 等并没有直接关系证据**。本轮改为：

- 技术关系**只依据真实关系数据**呈现（关系表：起点 → 关系 → 指向 + 证据状态 + 原文依据），方向与类型保持原样，未把反向关系翻转；
- 没有关系证据的方法作为**独立节点**单独列出；
- 发表顺序改为独立的**时间线**标签条，并明确写「仅表示发表先后，不代表技术继承」；
- 旧的「单一路线 + 箭头」页面不再出现在主流程中。

自动化断言：`时间线明确标注不代表技术继承`、`没有把相邻年份连成继承链` 均通过。
