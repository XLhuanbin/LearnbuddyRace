## 一、分析层实际改了什么

### 1. 方法家族与技术策略分离（`src/core/grouping.ts` 重写）

| 项目 | 之前的做法（问题） | 现在的做法 |
| --- | --- | --- |
| 判定范围 | 整段「核心思路」做关键词命中，CNN / Transformer / 蒸馏互斥 | **家族**只看「方法名称 + 核心思路首句」这类定义性文本；**技术策略**是来自全文的多标签 |
| 名称优先 | 无 | **方法名称优先**（作者对自己架构身份的表述）；名称无关键词时才看首句 |
| 引用语境 | 会把「CNN 教师 / 以 ResNet 为起点 / 引入 Swin 的设计」算成本方法的架构 | 新增 `stripReferenceMentions()`：剔除含「训练技巧 / 为起点 / 借鉴 / 参考 / 对照 / 教师 / baseline / 引入 / 沿用」等引用语境的片段后再判定 |
| 无法判定 | 强行归到某个家族 | 家族为 **待确认**，并说明「名称与首句都没有可判定的架构关键词，因此不强行归类」 |
| 依据 | 只有一个 keyword | 每条判定都记录 **依据来源（方法名称 / 核心思路首句）+ 命中关键词 + 原文片段**，界面上可展开核对 |

真实案例修正：ConvNeXt 的首句是「以 ResNet-50 为起点，先用视觉 Transformer 的训练技巧…」，
旧规则会判成「混合路线」；现在名称 `ConvNeXt` 命中 CNN 家族 → **判为卷积网络（CNN）**，
蒸馏/窗口注意力等只作为**技术策略标签**。

正式案例的真实结果（用 `scripts` 内的数据核对脚本跑出）：

```
视觉 Transformer 3 篇（ViT / DeiT / Swin）    卷积网络（CNN）2 篇（ResNet / ConvNeXt）    待确认 0
ResNet  → 家族 卷积网络（CNN）  策略 残差连接               依据：方法名称「ResNet」
ViT     → 家族 视觉 Transformer 策略 残差连接、Patch 嵌入    依据：方法名称「Vision Transformer」
DeiT    → 家族 视觉 Transformer 策略 知识蒸馏、数据高效训练   依据：方法名称「DeiT」
Swin    → 家族 视觉 Transformer 策略 窗口/移位窗口注意力、层次化多尺度、相对位置偏置  依据：方法名称「Swin」
ConvNeXt→ 家族 卷积网络（CNN）  策略 Patch 嵌入、大卷积核、深度可分离卷积/倒置瓶颈、高效训练设置
```

### 2. 概览统计口径修正

- **单篇内部先对数据集/指标去重**，再统计跨论文出现次数；因此「一篇论文里 ImageNet 出现两次」不再被算成两篇；
- 文案区分**全部 / 部分 / 未知**：正式案例输出「仅部分论文涉及：ImageNet（4/5 篇）、CIFAR-10（3/5 篇）…」；
- 不再声称全部论文都在做分类：输出「这组论文共 5 篇；其中 4 篇的研究任务描述里包含图像分类，
  其余 1 篇的任务描述没有出现「分类」字样（**不代表一定不涉及分类**，只是字段里没写到）」；
- 指标口径单独列出并提醒「准确率 / 错误率、top-1 / top-5 不能相互套用」。

### 3. 关系方向与语义

- 新增 `relationSentence(rel, viewerId, nameOf)`：从**任一端**查看都按 `from → to` 生成同一方向的说明，
  例如 ViT→DeiT 这条 `extends`：从 ViT 看是「DeiT 在 ViT 的基础上继续发展」，从 DeiT 看是
  「ViT 是 DeiT 的前置方法：DeiT 在此基础上继续发展」——不会讲反；
- **对称关系不加强方向**：`similar` / `unclear` 输出「X 与 Y 思路相近 / 关系不明确（未声明方向）」；
- 关系类型仍以数据为准（本轮核对了正式案例 10 条关系的类型与理由，未发现「把性能更好写成继承架构」的不一致，
  也未修改任何关系数据）；
- 关系解释直接取 `rationale`（推断理由），没有就如实说明「这条关系没有附解释文本」。

### 4. 直接复用的逻辑（未改）

PDF 解析、七字段抽取与原文定位校验、关系数据（方向与证据状态原样）、人工修正与迁移逻辑、缓存来源标记、
实验级比较 `compareExperiments`、阅读建议 `steps`、分歧分析、证据弹层、语料集隔离与幂等加载。

## 二、地图的实现（图形优先）

默认进入研究地图即渲染 `src/ui/MethodMap.tsx`：

| 元素 | 说明 |
| --- | --- |
| 泳道 | 用分区表达**方法家族**（卷积网络 / 视觉 Transformer / 混合 / 待确认），泳道标题带篇数 |
| 节点 | 一篇论文的一个方法：短名称 + 年份、**一句话贡献**（核心思路首句，最多两行）、最多 2 个技术策略标签；节点尺寸固定，不按质量/影响力变化 |
| 连线 | **只画真实关系**；颜色 + **线型**双重区分（实线=原文明示、虚线=系统推断、点线=待核查），箭头表示起点 → 指向 |
| 「关系不明确」 | **默认不连线**——它表示没有找到关系证据，连线会制造并不存在的联系；可用开关显示（标题栏显示已有多少条/多少对未画） |
| 待核查关系 | 默认不挤占主图，开关可显示 |
| 位置 | 只用于阅读组织；未做力导向漂移或粒子动画，也没有用距离表达语义 |
| 交互 | 点击节点 → 高亮它 + 直接相关节点与连线，其余弱化到 14% 透明度；右侧详情面板给出 ①解决什么问题 ②核心做法 ③与相关方法的具体区别，**原文依据折叠**；点击连线 → 一句话方向说明 + 证据状态 + 具体联系与变化 + 引文入口；支持缩放（70%~190%）、重置视图、关闭详情 |
| 窄屏 | 图形**不缩小**（保持文字可读），画布可左右滑动并给出提示；详情面板移到图形下方，适合触摸 |

实验比较仍降级为次级入口：在节点详情里点「比较实验表现（次级）」，或到「联系与区别」里展开。

## 六、剩余问题（如实列出）

1. **窄屏仍是横向滚动的泳道布局**：文字保持可读、可触摸滑动，但理想方案是按家族**纵向**堆叠泳道；本轮未做（记入下一步）。
2. **正式案例里「原文明示」为 0 条**：现有关系全部是系统推断（8 条）或待核查（2 条），因此实线图例在本案例中暂时用不到；
   这是数据真实状态，不是界面问题。
3. **两泳道共 5 个节点时地图较空**：当前只有 2 条可画关系；有更多论文（8–12 篇）时布局会更有价值，届时需要重新检查标签密度。
4. **家族规则仍是关键词规则**：对更细的领域（如点云、视频）需要补充关键词表；规则化保证可审计，但覆盖面有限，
   判不出的一律进「待确认」，不会硬塞。
5. **模型抽取成功路径仍未实测**（当前环境无可用密钥）：上传 PDF 的真实链路只走到「解析完成 + 就地提示配置」；
   抽取完成后的地图会走同一套渲染（已用缓存案例验证），但仍需一次真实抽取确认。
6. **自动化不等于用户理解**：本轮验证的是「元素可见、交互可点、证据归属正确」，是否真的让陌生用户快速看懂，
   仍需真人试用反馈。
